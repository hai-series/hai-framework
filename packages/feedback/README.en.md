# @h-ai/feedback

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

[Framework](../../README.en.md)

Collect user feedback and diagnostic evidence, notify administrators, review reports and export offline bundles. Descriptions are optional. Reports and structured evidence use a relational database; screenshots and binary attachments use private object storage. A separate telemetry service is not required.

## Quick Start

Initialize Core, RelDB and private Storage first. Initialize Reach as well when it delivers notifications.

Initialize the module at application startup. The submission function takes trusted server context and the ID generated by the client for this submission.

```ts
import type { FeedbackContext } from '@h-ai/feedback'
import { feedback } from '@h-ai/feedback'

// Configure feedback for orders, using console notifications for local development.
const initialized = await feedback.init({
  appId: 'orders',
  appVersion: '1.0.0',
  notificationMode: 'console',
  adminUrl: 'https://app.example.test/admin/feedback',
})
if (!initialized.success)
  throw new Error(initialized.error.message)

export async function submitFeedback(context: FeedbackContext, submissionId: string) {
  // Success returns a numbered report. Callers can read error on failure.
  return feedback.submit({ appId: 'orders', submissionId }, context)
}
```

At shutdown, check the result of `await feedback.close()` before closing its dependencies. Reuse the same `submissionId` on retries.

See the [feature reference](../../docs/usage/function/feedback.md) in Chinese for browser capture, HTTP routes and attachment retries.

## Configuration Reference

Generated projects use `config/_feedback.yml`, with `feedback.init(config, options)` as the application configuration entry point.

## Features

See the [feature reference](../../docs/usage/function/feedback.md) in Chinese for examples, inputs, outputs, error handling and usage notes.

- `init` / `close` / `isInitialized` / `config` / `budget` — Configure dependencies and read collection limits
- `submit` / `uploadAttachment` / `getAttachment` / `appendEvidence` / `completeCollection` — Submit reports, handle attachments and complete asynchronous evidence
- `list` / `get` / `getEvidence` / `setStatus` / `retry` / `runJobs` / `export` / `getExport` — Query, triage, retry and export reports
- `feedbackClient` / `bundle` / `capacitor` / `tauri` — Capture diagnostics, inspect offline bundles and save native files

## Development and Testing

```sh
pnpm --filter @h-ai/feedback typecheck
pnpm --filter @h-ai/feedback lint
pnpm --filter @h-ai/feedback build
pnpm --filter @h-ai/feedback test
pnpm --filter @h-ai/cli test:scaffold-gates
# After the builds above, verify the built viewer and replay in real Chromium without rebuilding dist.
node packages/cli/tests/feedback-offline-browser.mjs
```

Validate browser flows, SQLite/PG/MySQL, real S3 and SMTP, multi-instance recovery and disconnected bundle viewing separately. Build/mock success cannot replace those checks. See the [usage guide](../../docs/usage/README.en.md) for application integration and deployment.
