# 生成应用共同规则

本文件随 hai-app-create 完整目录交付。AGENTS 保留当前工程架构，公共约束在这里维护；先读 README、package.json、相关实现与测试，按任务读取所需 skill，不预加载全部参考。

## 需求与授权

- 业务以用户当前明确要求及其指定需求/设计文档为准；模板角色、权限、流程、字段、限额、存储和架构是初始实现。冲突时在已有授权内适配，同步 contract、鉴权、迁移、界面、配置、测试与过期规则，不要求把需求改回模板。
- 未说明的业务行为注明假设；只有实质矛盾、优先级不明或真实技术/安全障碍才提出具体问题。只读或仅规划请求不扩展为实现。
- 框架结构、配置、核心流程或模块边界的重要变化，按 [hai-change-plan](../hai-change-plan/SKILL.md) 说明方案与影响后等待决定；已确认且未扩大的方案不重复确认。普通应用私有实现沿已有授权推进。

## 实现与安全

- 先用 rg 查实现、引用、测试与文档，保留已有改动。优先复用真实适用的框架能力和公开类型；skill 已交付不表示模块已安装或启用。不为覆盖清单添加无关依赖、抽象或转发层。
- 按实际安装版本的 exports/types 核验契约。生命周期模块按依赖顺序 init → use → close，每步检查结果、失败清理、关闭反序；core/serv/kit、工厂、纯函数和流按实际签名使用。HaiResult 先判断 success，tx.wrap 返回失败结果不会自动回滚。
- 服务端校验输入、身份、权限及资源/租户归属；SQL 值参数化、标识符白名单、文件路径防逃逸。不把隐藏按钮当授权，不执行不可信 HTML/AI 内容。
- 密钥不进入 PUBLIC_/VITE_、浏览器或日志，敏感 token 不写 localStorage；沿现有 Cookie/内存或原生安全存储流程。用户提示准确且脱敏，日志保留英文操作上下文及可关联错误，未知提交不自动重放。
- 禁止 any、无说明的 as unknown as、console.log、硬编码密钥。注释中文，结构化日志英文且脱敏，用户文本沿现有 i18n 同步全部 locale。

## 代码注释与示例

- 尽可能补充有信息量的中文 JSDoc：所有 export 的函数/类/方法、核心算法与业务流程、所有数据库表/列、接口/type/schema 及其字段都必须说明用途、单位、约束和关联关系。核心逻辑解释决策原因、边界、权限与失败路径，不逐行复述代码。
- 函数按实际契约写 @param、@returns，仅确实抛错时写 @throws；异步、HaiResult 与事务失败行为须说明。类型/表结构说明字段含义、可空性、默认值、主外键和唯一约束。
- 上述函数和结构的 JSDoc 均提供可理解的 @example：函数给调用及结果判断，结构给合法数据，表给典型行或查询示例。省略上下文要标明，不使用真实凭据。示例随实现同步，不能只堆叠没有信息量的注释。
- 调用及结构示例见 [development.md](development.md) 的 JSDoc 注释一节。


## 同步与验证

按 [沟通与同步维护](collaboration.md) 先说明结论，区分已确认、待验证、计划、完成和未解决。跨边界变更核对实现、配置、注释、README、网站源、模板、调用方、i18n 与测试；共享任务沿 [交接契约](../hai-spec-implement/handoff.md) 续跑。

按真实差异、调用方和用户路径选择必要门禁，遵循 [分轮验证](../hai-app-tests/validation.md)，不默认全量重跑。UI/路由验证实际交互、失败恢复和适用尺寸/语言/主题；仅在新页面或明显改版时进入已交付的 hai-ui-design，组件实现用 hai-ui，真实页面走查用 hai-ui-review。纯 API 不加载 UI 路径。临时工程、进程、容器和数据在 teardown/finally 清理，只清理本次创建资源；证据放项目忽略目录。

完成时说明行为变化、实际复用、已执行门禁、同步文档/依赖方及未验证原因；文档修改明确是否影响运行时代码。
