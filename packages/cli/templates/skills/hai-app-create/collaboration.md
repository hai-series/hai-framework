# 沟通与同步维护

适用于框架/应用开发、审查、测试和问题排查。沿当前任务范围和授权执行；本约定不要求为小改动扩展审查或重跑全仓。

## 让结论可理解

- 先说明结论或本批解决的问题，再给必要依据。发现围绕“有什么问题、什么情况下发生、影响什么、怎么改”表达；例如“登录失败后仍跳转首页，用户看到空白页；先判断登录结果，失败时保留表单并显示可操作的提示”。
- 术语、路径和实现细节只用于支持结论。避免把搜索、命令和内部调用过程逐条复述给用户；简单问题简答，复杂问题按风险或用户流程分层。
- 清楚区分：**已确认**（源码或可复现证据）、**待验证**（说明缺少什么）、**计划修改**、**已完成**（列验证结果）、**尚未解决**（原因及下一步）。不要将猜测写成缺陷，将代码已改写成验收完成。
- 同一根因只列一次，合并受影响页面/模块。优先级由实际后果决定；审美偏好、环境限制、代码缺陷分开表述。
- 每批简述“解决什么、使用上有什么变化、如何验证、还剩什么”。复用既有稳定编号和任务状态，不另建重复台账；无发现时说明实际检查范围，不凑问题数量。

## 修改前与交付前的同步检查

框架相关任务先从四个视角提出可检验的要求，再查找差距：维护者需要稳定契约、清楚职责、失败可定位和同步成本可控；框架使用者需要可运行示例、可理解配置、明确环境边界和可恢复的调用流程；生成应用的最终用户需要清楚的信息层级、完整状态反馈、语言一致及键盘/窄屏可用；安全审查员关注服务端身份与资源权限、输入和外部地址边界、密钥与诊断材料保护，以及并发、重试和恢复中的权限绕过或重复副作用。每项问题说明触发条件、实际影响和验证办法，同一根因合并记录；不把四个视角机械扩展为本次范围外的大改造，也不把推测写成已确认漏洞。

按实际影响逐项作出“需同步 / 已同步 / 不适用及原因”的判断，不能机械要求每次全部修改：

| 对象 | 何时需要同步 | 应确认的结果 |
| --- | --- | --- |
| 使用文档 | 操作路径、环境前提、公开能力或故障恢复变化 | 更新 docs/usage 或项目既有使用指南；步骤可执行，限制清楚 |
| 配置与示例 | 配置名、默认值、校验、优先级或安全策略变化 | 核对 Schema 与消费点，区分框架默认、模板默认和建议值；示例能通过当前版本校验 |
| 截图 | 界面/交互或使用说明中的画面变化 | 当前版本实际操作后截图，记录场景、语言、尺寸；去除凭据与私人数据，不用旧图冒充新结果 |
| 测试 | 行为、权限、异常、并发或恢复边界变化 | 补最小合适层的行为回归；关键跨层流程保留 E2E，按影响定向运行 |
| CLI 模板 | 公共组件、配置、初始化或应用规范变化 | 新生成应用继承改进，验证复制后的文件、引用与核心流程；生成应用无框架仓库时不伪造仓库检查命令 |
| 调用方 | API、类型、错误码或共享默认变化 | 搜索直接及关键间接消费者；同步框架包、示例与模板，说明必要迁移 |
| README / Skills / AI 入口 | 使用方式或后续工作流程变化 | 共用正文与链接维护，已提供的多语言版本保持一致；不向应用复制仓库私有路径 |

## 使用文档与证据

按功能或安全项说明用途/适用场景、配置位置/名称/真实默认值、完整示例、前置与操作步骤、生效确认、实际影响和验证说明。没有默认值时明确标注；可选父配置未启用时，不能把子字段默认值写成已经启用。覆盖关系和环境差异应单独说明。

默认值以当前实现与实际消费点为依据，已安装应用以其安装版本为准。无界面配置可用脱敏请求响应、日志或验证结果说明。不能验证时写明环境、缺少的前提和可继续的步骤；静态校验、Mock、浏览器、容器、真实外部服务及原生安装的证据不能互相替代。

使用指南由理解源码和实际操作后人工编写，不用脚本将 Schema/API 表直接生成正文。自动化只做示例、链接、翻译键和截图采集等验证工作。截图解释“做了什么、看到什么变化”，优先展示操作前后和失败恢复，不能堆放无关图片。

统一提示的术语、语气和动作名称。面向用户说明发生了什么及下一步，开发定位用错误码和追踪标识连接日志；5xx/未知异常不显示内部细节。业务失败保留完整 HaiError，确需转换为异常时通过 Error.cause 保留来源。审查可见正文、占位符、按钮、校验、空状态、提示和辅助技术标签，不只检查翻译字典的键数；演示页和模板同样适用。

所有警告、错误及即时操作结果统一经 ToastContainer；不新增行内警告框、红色错误段落或页面私有提示浮层。字段保留错误标记、aria-invalid 和读屏关联说明，恢复动作留在原操作区域。默认仅显示可读说明，不显示 traceId；有编号时使用容器内“查看排查信息”图标，展开后显示“问题追踪编号”、复制入口及联系客户支持或开发人员时提供编号的说明。展开、悬停和聚焦期间暂停计时；验证复制失败的手动复制路径、键盘、弹窗和窄屏。中英日文同步，不把内部异常或敏感上下文放入排查面板。

临时截图、日志和验收报告遵守项目忽略目录规则；用户要求纳入使用指南的脱敏截图作为文档资产维护，标明采集条件。纯文档/规则改动明确说明没有运行时代码影响。

## 测试增删与排错

- 删除或合并测试前，对照触发条件、断言和风险覆盖，确认独有的权限、错误、恢复和跨层场景仍在；交付说明增删理由，不以数量或覆盖率百分比替代分析。
- 相同逻辑可参数化，但不同后端或不同安全边界不是无价值重复。单元测试聚焦确定性逻辑，集成测试验证真实适配/存储，E2E 验证用户任务与跨层衔接。
- 排错先给可复现的现象、影响和下一步，再附错误码、traceId、已脱敏上下文；不索取或回显密钥。失败后按 [分轮验证](../hai-app-tests/validation.md) 归并根因、定向复测，保留未通过证据。
