# 能力、边界与应用结构

[认识框架](README.md) · [选择阅读路线](reading-paths.md)

hai-framework是TypeScript应用框架，提供AI调用、身份和权限、数据、页面、通知、审计及交付能力。你可以只调用模型，也可以按需组合成企业应用；安装某个包不代表它需要的外部服务已经可用。

## 从一个能力开始

调用聊天模型时，先接服务端AI和可信模型凭据。需要保留会话再接持久Store，需要企业知识检索再增加文本处理、embedding和向量后端。页面只展示Markdown或文档编辑器时，可以只用UI，无需先连模型。

数据与安全模块各自有公开契约。RelDB、Cache、IAM等有初始化和关闭；Datapipe是函数；Serv是HTTP工厂；Kit是宿主适配；UI是组件。返回HaiResult的业务操作先判断success，不能把失败当成正常data。

## 选择应用结构

### 同源Web

一个SvelteKit应用承载页面和API，使用Kit衔接请求、认证与标准响应。适合后台管理、企业站、H5等单一Web工程。

### 独立API或多端应用

api-contract定义输入输出，Serv在Node提供API，api-client负责类型调用。fullstack模板把contract、服务、共享内容与web/app/desktop分开；多端共用契约和服务端权限，不在每个界面重复业务判断。

### 原生与容器交付

容器交付时，`serv` 和 `web` 分别表示后端与浏览器站点服务；`app` 和 `desktop` 表示手机、桌面安装包。纯静态website也可直接托管到GitHub Pages，无需启动容器。编译源码、构建镜像、生成安装包和部署是不同步骤，浏览器可运行不能代替手机或生产部署验收。

## 生产采用的条件

启用数据库、会话、文件或向量等有状态能力时，生产即使只有一个实例，也须满足所选模块的共享后端要求，并备份凭据与数据。没有这些能力的纯静态站点不需要为了上线额外安装数据库或Redis。

依赖故障、超时、并发和结果未知的外部操作要有明确恢复路径。Compose更新会替换所选容器，可能短暂停机；它不自动恢复已写业务数据或数据库结构，也不承诺零停机。

模块清单和完整API见[框架README](../../../README.md)。本文档的配置、页面图与验证范围以当前实现为准，尚未完成的真实外部环境验收在[验证说明](../governance/verification.md)中单列。
