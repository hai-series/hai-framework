# 主な機能とアプリ構成

[章の概要](README.ja.md) · [目的別の読み方](reading-paths.ja.md)

hai-framework は、AI、認証と認可、データ、UI、通知、監査、アプリの配布に使える TypeScript フレームワークです。必要なパッケージを一つだけ使うことも、複数組み合わせてアプリを作ることもできます。パッケージが外部サービスを利用する場合は、アプリを実行する前に準備してください。

<a id="adopt-one-feature"></a>

## まず一つの機能を使う

チャットではサーバー側の AI API を使い、モデルの認証情報もサーバーに置きます。会話履歴を残す場合は永続ストアを、ナレッジ検索が必要ならテキスト処理、埋め込み、ベクトルストアを追加します。Markdown の表示や文書の編集には UI パッケージ単体で使えます。

エージェントにプロジェクトを操作させるには、[ACP のプロジェクトセッション](../development/ai-acp.md) を参照してください。ローカル、コンテナ、リモートの HTTP/WS サービスから選び、モデルを設定してワークスペースを登録します。Git プロジェクトごとにメインブランチを指定し、セッションでディレクトリを共有するか worktree を分けるかを選びます。更新と公開は明示的に行います。

RelDB、Cache、IAM には初期化と終了のメソッドがあります。Datapipe は呼び出したときに処理を実行します。Serv は HTTP アプリを作成し、Kit は SvelteKit と連携し、UI はコンポーネントを提供します。`HaiResult` が返る場合は `success` を確認してから `data` を使ってください。

<a id="application-structure"></a>

## アプリの構成を選ぶ

| 構成 | 各パッケージの役割 |
| --- | --- |
| 同一オリジンの Web アプリ | 一つの SvelteKit アプリでページと API を提供します。Kit はリクエスト、認証、レスポンスを連携します。管理画面、企業サイト、モバイル向け Web アプリに適しています。 |
| 独立した API または複数クライアント | API Contract で入出力を定義し、Serv で Node 上の API を提供し、API Client から型付きで呼び出します。fullstack テンプレートは API 定義、サーバー、共有コード、Web・モバイル・デスクトップを別々のワークスペースに分けます。各クライアントは共通のサーバーで認可されます。 |
| コンテナとネイティブアプリの配布 | `serv` と `web` はコンテナサービス、`app` と `desktop` はインストーラーを表します。静的サイトは GitHub Pages でも公開できます。作成した成果物は対象環境で検証します。 |

<a id="production"></a>

## 本番環境に必要なもの

データベース、セッション、ファイル、ベクトルを永続化する項目を有効にする場合は、各モジュールに必要なバックエンドを用意し、データと認証情報をバックアップします。アプリが 1 インスタンスでも同様です。永続化を利用しない静的サイトはファイルを配置して公開できます。

外部サービスの障害やタイムアウト、処理結果が分からない場合に備え、復旧手順を決めておきます。Compose がコンテナを置き換える間は短い停止が発生することがあります。書き込み済みのデータやスキーマはアプリ側の手順で復旧してください。[モジュール API](../function/README.ja.md) · [検証ガイド](../governance/verification.md)
