# cache 数据结构

[数据结构索引](README.md) · [模块配置](../configuration/cache.md) · [功能说明](../function/cache.md)

## 数据库

模块不创建 SQL 表。Redis 的逻辑数据库编号由连接配置选择，memory 将相同逻辑结构保存在当前进程。

## 缓存键

| 操作类别 | 逻辑键和值                                               | 默认值与 TTL                                                       |
| -------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| `kv`     | 业务键；普通值使用 JSON 序列化，计数接口可以原子读写数值 | 缺失读取为 null；设置时可选秒 `ex` 或毫秒 `px`。CAS 可保留现有 TTL |
| `hash`   | 业务键；字段名到值的映射                                 | 单独字段无 TTL；可对整个键设置过期                                 |
| `list`   | 业务键；按顺序保存元素，允许重复                         | 对整个列表设置过期                                                 |
| `set_`   | 业务键；不重复的成员                                     | 对整个集合设置过期                                                 |
| `zset`   | 业务键；成员及其数值分数                                 | 对整个有序集合设置过期                                             |
| `lock`   | `__lock:<业务键>`；值为持锁 token                        | 默认租约 30 秒。续租或释放时核验 token                             |

通用读写以调用方的 key 为逻辑标识。Redis 配置 `keyPrefix` 后，物理键带此前缀。扫描返回逻辑键，删除、过期和存在性检查针对整个键。集群多键原子操作要求同一 hash slot，例如使用相同的 Redis hash tag。清空和批量维护前应确认业务键与其他模块的使用范围。
