## 这些数据用来做什么

先看用途和例子，再按需查后面的字段与保存规则。例子中的编号和业务内容是虚构的，敏感值已隐藏。时间以 2026-11-17 00:00 UTC 为起点，具体单位在说明中标明。

### 临时保存一个数

对应结构：`orders:total`。

用于暂存业务计数，减少反复计算；需要并发加减时使用 Cache 的原子计数操作。

```json
3
```

total 是业务自己取的名字，值 3 表示该业务计数为三；它不是 Cache 的全局键数量。

### 临时保存一份资料

对应结构：`orders:profile:42`。

用于让后续请求复用已查询的用户资料，资料变化时由业务更新或删除。

```json
{
  "id": "user-42",
  "name": "Example"
}
```

这是 user-42 的示例资料。设置 ex:60 时60秒后删除；不指定期限就不会自动到期。

### 按字段修改资料

对应结构：`orders:profile-fields:42`。

Hash 适合只更新资料中的某一项，而不重写整份对象。

```json
{
  "name": "Example",
  "status": "active"
}
```

name 和 status 是两个独立字段；期限作用于整条 Hash，不能只让 status 过期。

### 按顺序保存待处理编号

对应结构：`orders:queue`。

List 用于按先后顺序放入、取出编号，允许相同值重复出现。

```json
[
  "order-42",
  "order-43"
]
```

order-42 排在 order-43 前面。仅有列表不保证任务只执行一次，可靠任务使用 Runner 等业务服务。

### 保存不重复的成员

对应结构：`orders:tags`。

Set 用于判断某个标签或成员是否存在，相同成员加入两次仍只保留一份。

```json
[
  "new",
  "paid"
]
```

示例集合含 new、paid；数组只是查看成员的方式，集合本身不保证顺序。

### 按分数排列成员

对应结构：`orders:scores`。

ZSet 用于排行榜或按数值排序的集合，每个成员对应一个分数。

```json
[
  {
    "member": "user-42",
    "score": 8
  }
]
```

user-42 的分数为 8；score 是排序依据，不是成员出现次数。

### 短时间内由一个处理者持锁

对应结构：`orders:__lock:invoice-42`。

用于让竞争者暂时互相避让，持锁方释放或续期时必须证明自己仍拥有它。

```json
"<lock-token:redacted>"
```

值是本次持锁凭据，已脱敏；默认30秒后失效。它不能替代业务最终写入时的版本或唯一约束。

## 字段、存储与清理参考

### 数据库

模块不创建 SQL 表。使用 Redis 时，连接配置决定写到哪个 Redis 数据库。使用内存模式时，键和值只保存在本次运行的进程里，进程重启后清空。

### 缓存键

| 操作类别 | 逻辑键和值                                               | 默认值与 TTL                                                                                                    |
| -------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `kv`     | 业务键；普通值使用 JSON 序列化，计数接口可以原子读写数值 | 键不存在时读到 `null`。设置值时可用 `ex` 指定多少秒后过期，或用 `px` 指定毫秒。按旧值更新时可保留原来的过期时间 |
| `hash`   | 业务键；字段名到值的映射                                 | 单独字段无 TTL；可对整个键设置过期                                                                              |
| `list`   | 业务键；按顺序保存元素，允许重复                         | 对整个列表设置过期                                                                                              |
| `set_`   | 业务键；不重复的成员                                     | 对整个集合设置过期                                                                                              |
| `zset`   | 业务键；成员及其数值分数                                 | 对整个有序集合设置过期                                                                                          |
| `lock`   | `__lock:<业务键>`；值为持锁 token                        | 默认持锁 30 秒，过期后其他调用可获得锁。续期或释放时要匹配取得锁时的令牌                                        |

读写时传入原始键名。例如配置 `keyPrefix: "orders:"` 后，`cache.kv.set("total", 3)` 的 Redis 键是 `orders:total`，扫描结果仍叫 `total`。删除、过期和检查是否存在都以整键为单位。Redis 集群只有把多个键放在同一哈希槽，才允许一次原子操作修改它们，可以用 `{order42}:items` 和 `{order42}:count` 这样的共同标签。批量清理前请确认匹配哪些键，避免碰到其他业务的数据。
