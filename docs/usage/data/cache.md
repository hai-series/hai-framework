## 数据库

模块不创建 SQL 表。使用 Redis 时，连接配置决定写到哪个 Redis 数据库。使用内存模式时，键和值只保存在本次运行的进程里，进程重启后清空。

## 缓存键

| 操作类别 | 逻辑键和值                                               | 默认值与 TTL                                                                                                    |
| -------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `kv`     | 业务键；普通值使用 JSON 序列化，计数接口可以原子读写数值 | 键不存在时读到 `null`。设置值时可用 `ex` 指定多少秒后过期，或用 `px` 指定毫秒。按旧值更新时可保留原来的过期时间 |
| `hash`   | 业务键；字段名到值的映射                                 | 单独字段无 TTL；可对整个键设置过期                                                                              |
| `list`   | 业务键；按顺序保存元素，允许重复                         | 对整个列表设置过期                                                                                              |
| `set_`   | 业务键；不重复的成员                                     | 对整个集合设置过期                                                                                              |
| `zset`   | 业务键；成员及其数值分数                                 | 对整个有序集合设置过期                                                                                          |
| `lock`   | `__lock:<业务键>`；值为持锁 token                        | 默认持锁 30 秒，过期后其他调用可获得锁。续期或释放时要匹配取得锁时的令牌                                        |

读写时传入原始键名。例如配置 `keyPrefix: "orders:"` 后，`cache.kv.set("total", 3)` 的 Redis 键是 `orders:total`，扫描结果仍叫 `total`。删除、过期和检查是否存在都以整键为单位。Redis 集群只有把多个键放在同一哈希槽，才允许一次原子操作修改它们，可以用 `{order42}:items` 和 `{order42}:count` 这样的共同标签。批量清理前请确认匹配哪些键，避免碰到其他业务的数据。
