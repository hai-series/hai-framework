## 数据库

为 HTTP 加密选择 RelDB 密钥存储时，模块创建下列三张表来保存客户端公钥和已处理过的请求标识。单独计算哈希、签名、加密或解密时，模块不会把消息正文或私钥写入这些表。

| 表                                 | 字段与约束                                                                                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hai_crypto_transport_client_keys` | `client_id` 为注册客户端主键，`public_key` 为 SM2 公钥，`created_at_ms` 为登记时间。可空 `expires_at_ms` 为到期时间，省略公钥 TTL 时为 NULL               |
| `hai_crypto_transport_requests`    | `request_key` 为客户端及请求标识组成的 JSON 数组字符串，作为唯一键记下已登记的请求，`expires_at` 存该记录到期的毫秒时间。有效期内再登记同一个请求会被拒绝 |
| `hai_crypto_transport_capacity`    | `id` 为单行主键 1，`max_clients` 为允许同时登记的客户端上限，默认 10000。`revision` 从 0 开始，容量更新时改变。各服务实例使用同一上限                     |

登记和清理记录时以数据库时钟为准。公钥和请求记录各自有到期时间，后续操作会分批删除已经到期的记录。

## 缓存键

| 逻辑键                                                | 值                                         | 默认值与到期                                           |
| ----------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| `hai:crypto:transport:client:<clientId>`              | SM2 客户端公钥                             | `ttlSeconds` 指定公钥寿命，省略时不过期                |
| `hai:crypto:transport:request:<clientId>:<requestId>` | `true`，表示此请求已登记，用于识别重复请求 | 原子写入，TTL 为当前时间距该请求认证窗口截止点的毫秒数 |

使用 Redis 或 Redis Cluster 存储时，连接和键前缀取自 [cache](cache.md)。生产环境需要让请求记录保留到期，避免因 Redis 提前删除键而失去重复请求检查。选用内存存储时，各进程只看得到自己记录的公钥和请求。
