## それぞれの記録の役割

まず用途と例を読み、必要に応じて後半の項目・保存規則を確認してください。ID と業務内容は架空で、秘密は隠しています。時刻は 2026-11-17 00:00 UTC を起点とし、単位は各説明に記します。

### 成功結果

対応する構造：`success`。

呼び出し側が成功後のデータを読むための値です。

```json
{
  "success": true,
  "data": {
    "id": "order-42",
    "status": "created"
  }
}
```

order-42 の作成が成功し、data に結果が入っています。

### 失敗結果

対応する構造：`failure`。

失敗時に処理停止や通知を判断する値です。

```json
{
  "success": false,
  "error": {
    "code": "hai:core:001",
    "message": "Example failure",
    "httpStatus": 500
  }
}
```

success が false なら error を読みます。message は説明用で、実際には翻訳済みの文言を使います。

### このプロセスが読み込んだ設定

対応する構造：`loaded configuration`。

検証済み設定をメモリから読むための値です。

```json
{
  "name": "Orders",
  "env": "development",
  "defaultLocale": "zh-CN"
}
```

core 設定の一部で、再読込はアプリが管理し、他プロセスとは自動共有しません。

### 追跡できるログ1件

対応する構造：`LogRecord`。

出来事と関連するリクエスト番号を記録します。

```json
{
  "timestamp": 1794873600000,
  "level": "info",
  "message": "Order created",
  "context": {
    "requestId": "request-42"
  }
}
```

時刻は Unix ミリ秒で request-42 を関連付けます。保存先はログ後端が決めます。

### 1回のリクエストで共有する追跡情報

対応する構造：`RequestContext`。

複数手順で同じ追跡番号を使います。

```json
{
  "requestId": "request-42",
  "scopeId": "team-1",
  "userId": "user-42"
}
```

team-1 の user-42 で、令牌を含まず、この情報自体は操作を許可しません。

### アプリの依存が起動済みか

対応する構造：`ModuleRuntime`。

順に開始・逆順に終了し、未準備の利用を防ぎます。

```json
{
  "isInitialized": true
}
```

JSON には起動済み状態だけを示し、関数や DB 永続状態ではありません。

### ワーカープールと終了状態

タスクと応答は同一プロセスのプールに属します。所有者が閉じると待機中と実行中の処理が解放されます。以下はブラウザーの専用スレッドを所有者が停止したときの終了結果です。Node ではスレッドの終了コードが `code`、スレッドのエラーがある場合は `error` に入ります。

```json
{
  "code": 0
}
```

## 項目・保存・削除のリファレンス

Core は以下のデータを実行中のプロセスのメモリに保持します。データベースのテーブルや Redis のキー、ディスクキャッシュは作成しません。Node プロセスごとに必要な設定を読み込みます。

| データ               | 内容                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 読み込み済み設定     | `core` などの名前で保存され、`core.config.get('core')` で取得します。検証時に補われる既定値はスキーマで決まります |
| ログ                 | レベル、時刻、関連情報。出力と保持期間はログのバックエンドが決めます                                              |
| モジュールの実行状態 | アプリが起動したモジュール、依存関係、現在の状態。新しいプロセスでは改めて起動します                              |
| リクエストと処理結果 | 同じリクエスト内で共有する追跡情報と、処理が返す成功値またはエラー                                                |
