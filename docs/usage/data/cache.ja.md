# @h-ai/cache データ構造

[简体中文](cache.md) · [English](cache.en.md)

[データ構造一覧](README.ja.md) · [設定](../configuration/cache.ja.md) · [API リファレンス](../function/cache.ja.md)

アプリは注文数、プロフィールのスナップショット、処理待ち ID などを Cache に保存できます。同じ処理を担当するワーカーはロックで調整でき、プロセス間で共有できるかはバックエンドによって決まります。

Cache は SQL テーブルを作りません。Redis では接続設定のデータベースに保存します。メモリーモードは現在のプロセスで保存し、終了すると消えます。

<a id="cache"></a>

## キャッシュ

Cache は 6 種類のキーを扱います。業務キーの名前と値は呼び出し元が決めます。例ではアプリの接頭辞を `orders:` にしています。

| キーまたは種類 | 用途 | 既定の期限と削除 |
| --- | --- | --- |
| [`kv`](#cache-cache-kv) | 値の一時保存やカウンターの更新に使います。 | 既定で期限なし。`ex` は秒、`px` はミリ秒です。旧値を照合して更新するときは `keepTtl` を使えます。 |
| [`hash`](#cache-cache-hash) | 必要な項目だけ読み書きします。 | 既定で期限なし。キー全体に期限を設定できます。 |
| [`list`](#cache-cache-list) | 処理する項目を順に保持します。 | 既定で期限なし。リスト全体に期限を設定できます。 |
| [`set_`](#cache-cache-set) | メンバーを重複なしで保存します。 | 既定で期限なし。集合全体に期限を設定できます。 |
| [`zset`](#cache-cache-zset) | メンバーを点数順に並べます。 | 既定で期限なし。ソート済み集合全体に期限を設定できます。 |
| [`__lock:<key>`](#cache-cache-lock) | 一つの処理が短時間だけ業務ロックを保持します。 | 既定で 30 秒。同じ `owner` で延長・解放します。最後の解放か期限到達でキーを削除します。 |

<a id="cache-cache-kv"></a>

### `kv`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| 値全体 | JSON | — | 業務データ全体を保存します。キーがなければ `null` を返します。 | `orders:profile:42` → `{"id":"user-42"}` |
| カウンター | `number` | — | カウンター操作で数値をアトミックに更新します。 | `orders:total` → `3` |

<a id="example-data"></a>

<a id="一時的な数値"></a>

#### 例 · 一時的な数値

業務の数値を一時保存し、同時更新には原子的な計数操作を使います。

```json
3
```

total は業務で付けた名前で、3 はその計数です。Cache 全体のキー数ではありません。

<a id="資料の一時保存"></a>

#### 例 · 資料の一時保存

取得済みの資料を次のリクエストで再利用します。変更時は業務側で更新・削除します。

```json
{
  "id": "user-42",
  "name": "Example"
}
```

`user-42` のプロフィールです。書き込み時に `ex: 60` を指定すると、書き込みから 60 秒で失効します。有効期限を省略した場合は、アプリが必要に応じて更新または削除します。

<a id="cache-cache-hash"></a>

### `hash`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| fields | `string` → JSON | — | アプリが項目名を決め、個別に読み書きします。 | `orders:profile-fields:42` → `{"status":"active"}` |

<a id="項目ごとの資料更新"></a>

#### 例 · 項目ごとの資料更新

Hash は一項目だけを変更する用途です。

```json
{
  "name": "Example",
  "status": "active"
}
```

name と status は別項目ですが、期限は Hash 全体にかかり、status だけは失効させられません。

<a id="cache-cache-list"></a>

### `list`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| elements | JSON array | — | 順序を保持し、値の重複を許可します。 | `orders:queue` → `["order-41","order-42"]` |

<a id="処理順を持つ一覧"></a>

#### 例 · 処理順を持つ一覧

List は順番を保ち、同じ値も複数入れられます。

```json
[
  "order-42",
  "order-43"
]
```

order-42 が先です。これだけでは一度だけの実行を保証せず、永続タスクには Runner 等を使います。

<a id="cache-cache-set"></a>

### `set_`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| members | set of strings | — | メンバーは一度だけ保持します。順序は保証しません。 | `orders:tags` → `["paid","priority"]` |

<a id="重複しないメンバー"></a>

#### 例 · 重複しないメンバー

Set は存在確認に使い、同じ値を追加しても一つだけ残します。

```json
[
  "new",
  "paid"
]
```

new と paid を含み、表示の配列順は保証されません。

<a id="cache-cache-zset"></a>

### `zset`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| member | `string` | — | 集合内の一意のメンバー。 | `order-42` |
| score | `number` | — | 並び替えに使う点数。キーの例は `orders:scores` です。 | `99` |

<a id="点数順のメンバー"></a>

#### 例 · 点数順のメンバー

ZSet は数値順の一覧や順位表に使います。

```json
[
  {
    "member": "user-42",
    "score": 8
  }
]
```

user-42 の点数は8で、出現回数ではなく並び順の基準です。

<a id="cache-cache-lock"></a>

### `__lock:<key>`

| 値の項目 | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| owner | `string` | — | 初回取得時に保存するトークン。業務キー `invoice-42` は `__lock:invoice-42` に対応します。 | `<lock-token:redacted>` |
| depth | `integer` | `1` | 同じ所有者が複数回取得すると、深さを同じ文字列に記録します。 | `<lock-token:redacted>\|2` |

Hash、List、Set、ZSet の最後の要素を削除すると、キーと期限が消えます。同じ名前で作り直した集合には期限がありません。

Cache には論理キーを渡します。`keyPrefix` が `orders:` なら、`total` の Redis キーは `orders:total` になります。スキャン結果では `total` が返ります。Redis Cluster の複数キー操作をアトミックに行うには、`{order42}` のようなタグで同じハッシュスロットに置きます。

<a id="短時間のロック所有者"></a>

#### 例 · 短時間のロック所有者

論理キーは `__lock:invoice-42` です。Redis で `keyPrefix` が `orders:` の場合、保存キーは `orders:__lock:invoice-42` になります。Redis と Memory はどちらも、所有者と取得回数を一つの文字列に保存します。

`invoice-42` を最初に取得すると、呼び出し元に返した所有者トークンを保存します。以下の例ではトークンを伏せています。既定のリース期間は初回取得から 30 秒です。

```json
"<lock-token:redacted>"
```

所有者が `cache.lock.acquire('invoice-42', { owner })` で再取得すると、同じ `owner` が返り、取得回数が一つ増えます。元の有効期限は維持されます。2 回目の取得後に保存される値は次のとおりです。

```json
"<lock-token:redacted>|2"
```

最初の `release` は成功データとして `data: true` を返し、取得回数を一つ減らして値をトークンだけに戻します。ロックは保持されたままで、次の解放でキーが削除されます。延長には同じ `owner` が必要です。有効期限に達すると、取得回数にかかわらずキー全体が削除されます。最終書き込みでは、バージョンや一意性を別途確認します。
