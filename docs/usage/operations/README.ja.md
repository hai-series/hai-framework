# リリースと運用

[ガイドのトップ](../README.ja.md) · [初回リリースの手順](../getting-started/workflow.ja.md)

デプロイ前に成果物、対象環境、前回成功したリリースを確認し、デプロイ後にユーザー操作を一通り試します。タイムアウトや SSH の切断があった場合は、再試行する前に対象環境から実際の状態を確認してください。

## デプロイを計画して実行する

[デプロイ手順](deployment.md) では、読み取り専用の計画、全体・差分リリース、ヘルスチェック、バージョンの確認を扱います。設定項目、秘密情報の取得元、前回リリースに必要な条件は [デプロイ設定](../configuration/delivery.md) を参照してください。非公開の環境変数の値は端末に出力しないでください。

## 復旧とロールバック

デプロイ結果、リモートの `current` レコード、稼働中のコンテナを照合すると、復旧済み、復旧失敗、結果不明を区別できます。ロールバックには、以前の成果物と対応する設定を使って新しい全体デプロイを行います。データの変更と外部システムへの影響はアプリ側の手順で復旧します。[失敗時の復旧とロールバック](../configuration/delivery.md#失败恢复与发布后回滚)

## フィードバックとバックグラウンドジョブの調査

ユーザーに表示された受付番号から調査を始めます。[フィードバック・ジョブ・障害調査](feedback.md) では、受付、通知、Webhook、監査、ジョブ実行をログで追う流れを説明します。制限時間、受領確認、保持期間は [運用設定](../configuration/operations.md) を参照してください。

## 検証した範囲を記録する

テスト用のデータやサービス、実アプリ、実際のバックエンド、公開ゲートウェイのうち、どの環境で確認したかを記録します。それぞれ検出できる問題が異なります。[検証ガイド](../governance/verification.md)
