# 发布与日常运行

[文档首页](../README.md) · [运维部署路线](../overview/reading-paths.md#运维部署人员发布可定位失败能判断和恢复)

发布和运行都以业务结果为准。先核对制品、环境和基线，再发布，再做用户流程；出现问题时保留现场并判断实际状态，不因超时或SSH退出直接重发。

## 发布前与发布中

按[部署操作](deployment.md)执行只读计划、全量或增量、健康与版本检查。参数、秘密来源、基线要求和回滚条件见[部署配置](../configuration/delivery.md)，不要在操作机打印完整私有环境。

## 发布失败或需要回退

先读结果文件/current/实际容器，区分恢复passed、failed和远端unknown。主动回退使用旧制品与匹配配置生成新全量部署ID；数据库/Schema和外部副作用按独立方案处理。完整顺序见[失败恢复与发布后回滚](../configuration/delivery.md#失败恢复与发布后回滚)。

## 日常问题与后台任务

[反馈、任务与排错](feedback.md)从用户受理编号开始，区分采集、通知、Webhook、审计和调度结果，再把追踪编号关联到日志。配置预算、回执与保留集中见[运行配置](../configuration/operations.md)。

## 验证边界

部署脚本夹具、真实应用、真实数据库和公网入口分别承担不同证据。按[验证说明](../governance/verification.md)报告环境，不把配置通过或本地打包称为生产验收。
