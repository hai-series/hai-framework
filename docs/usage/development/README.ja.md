# 機能別の開発ガイド

[ガイドのトップ](../README.ja.md) · [設定リファレンス](../configuration/README.ja.md)

実装する業務フローに合ったガイドを選んでください。各ページでは機能の組み合わせ方を説明し、使う設定項目へのリンクを掲載しています。

## リクエストとデータの境界を決める

独立した API や複数クライアントがある場合は、[フロントエンド・バックエンド・API 認可](frontend-backend.md) で、API の入出力、サーバーの権限チェック、クライアントの役割を確認してください。レコードの保存やファイルのアップロードには [データ・トランザクション・添付ファイル](data.md) を参照し、失敗と再試行で一部だけ保存されたり重複したりしないことを確認します。

## 認証と画面をつなぐ

[ログイン・パスワード変更・ログアウト](authentication.md) では、ログイン、アクセスの回復、セッションの無効化を扱います。[レイアウトと操作](ui.md) では、フォーム、一覧、ダイアログ、テーマ、トーストに加え、読み込み中、空の状態、エラー時の表示を説明します。操作ごとの権限はサーバーで確認します。

## 必要に応じて外部サービスをつなぐ

[AI コンテンツ・モデル・検索](ai.md) はコンテンツの表示から始め、モデルの呼び出しと永続化を追加します。[決済とネイティブ機能](integrations.md) は、ローカル、決済サービスのサンドボックス、実機で確認する内容を示します。

エージェントにプロジェクトを操作させる場合は、[ACP エージェント・ワークスペース・セッション](ai-acp.md) を参照してください。ローカル、コンテナ、リモートからサービスを選び、Git ワークスペースごとにメインブランチを指定して、セッション、worktree、公開の手順を確認します。[マルチユーザーのエージェントワークスペース](agent.md) では、ログイン、ACP、ナレッジ、メモリ、音声、ツールフォーム、編集可能な成果物を一つのアプリにまとめます。[アプリ説明](../../../apps/agent/README.ja.md) も参照してください。

## Node SSR のビルド成果物を起動する

現在の SvelteKit adapter-node 6 は、`kit.paths.origin` も設定済みのプロトコルヘッダーもない場合、`https` として URL を構成します。Node のポートに平文 HTTP で直接アクセスすると、オリジンの不一致によりフォーム POST が 403 になることがあり、実行時の `ORIGIN` 変数は使われません。プロジェクト既存のビルド・起動スクリプトを使い、信頼できるリバースプロキシを経由します。たとえば Node の起動前に `PROTOCOL_HEADER=x-forwarded-proto` と `HOST_HEADER=x-forwarded-host` を設定し、プロキシで受信した転送ヘッダーを除去して、公開 Host を検証し、プロトコルと Host のヘッダーを再構成します。バックエンドにはプロキシからだけ接続できるようにし、HTTPS の TLS はプロキシで終端します。`kit.paths.origin` を固定する方法もありますが、成果物に埋め込まれるため、ホスト名やプロトコルの変更には再ビルドが必要です。実行時のプロキシ設定なら同じ成果物を環境間で利用できます。

## 一連の操作を検証する

成功、権限による拒否、失敗からの復旧を一度ずつ試します。運用時の問題は [フィードバックと障害調査](../operations/feedback.md)、各検証で確認できる範囲は [検証ガイド](../governance/verification.md) を参照してください。

利用者と同じ package scripts を使います。通常の起動検証は実際のプロジェクトで `pnpm dev` を実行し、公開・非公開の環境ファイルを通常どおり読み込みます。アプリ設定の注入、代替鍵の生成、初期パスワードの置換は行いません。フロントエンドは実際のブラウザで実行し、ページまたは health へのアクセスでサーバーを初期化します。通常の E2E は短い Playwright 設定から既存の `dev:test`、`start:test`、`preview` を呼び出します。開発起動、テストモードの成果物、本番バックエンドは別々に報告します。

開発・テスト用のサンプル鍵は `.env.dev` と `.env.test` にあり、本番では別の非公開鍵を使います。初期パスワード変更、短いセッション、通知などの専用テストはテストディレクトリーに用途を明記し、終了後にモードファイルを復元します。専用シナリオを通常起動の検証に代用しません。
