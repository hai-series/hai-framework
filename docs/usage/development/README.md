# 按业务能力开发

[文档首页](../README.md) · [开发人员路线](../overview/reading-paths.md#开发人员把业务能力接成可恢复流程)

从本次业务流程需要的能力开始。每页说明如何接入和操作，对应参数统一指向配置手册；不用先读完所有模块。

## 先确定请求和数据边界

多端/独立API先读[前后端与授权](frontend-backend.md)，把contract、服务端权限和客户端分清。需要保存业务数据时接[数据、事务与附件](data.md)，确认失败不会误提交或重复写入。

## 再接身份和页面

[登录、改密与退出](authentication.md)验证用户能进入、能恢复并能撤销会话；[页面布局和交互](ui.md)处理表单、列表、弹窗、主题与Toast，验证加载/空态/失败和重复提交。按钮隐藏不代替服务端授权。

## 按需增加外部能力

[AI内容、模型与检索](ai.md)先显示、再调用、再持久化；[支付与原生能力](integrations.md)分清本地验证、渠道沙箱和真实设备，不能以Mock成功替代实际结果。

## 结束时核对跨层流程

至少验证一条成功、一条拒绝和一次失败恢复。配置查[领域手册](../configuration/README.md)，问题处理见[反馈与排错](../operations/feedback.md)，门禁职责和证据见[验证说明](../governance/verification.md)。
