## Configuration entry

A SvelteKit service generated by the CLI loads `config/_kit.yml` with Core and validates it with `KitConfigSchema`. In `hooks.server.ts`, the app passes `http`, `cors`, and the enabled transport settings to `kit.createHandle()`. When enabling A2A, supply the AI protocol handler and authentication. The server supplies the key ring and shared key registry. The browser receives the public transport settings it needs. [Hook arguments](../function/kit.en.md#host-options)

When Core loads this configuration, `HAI_KIT_<FIELD_PATH>` can override YAML. For example, `HAI_KIT_HTTP_TRUSTEDPROXIES` maps to `http.trustedProxies` and `HAI_KIT_TRANSPORT_MAXREQUESTAGESECONDS` maps to `transport.maxRequestAgeSeconds`. Within one source, a whole-object value provides the base and individual fields override it. The process environment takes precedence over mode-specific private, global private, mode-specific public, and base environment files. A setting takes effect when the application loads it and passes it to the consumer. [Configuration sources and precedence (Chinese)](runtime.md#配置从哪里来)

The example admin console explicitly binds proxy, access, listener, and transport settings in `_kit.yml`. The SvelteKit template configures transport for the selected features and uses Core and the schema to read `HAI_KIT_` overrides. In a generated project, `pnpm start` uses adapter-node, which reads `HOST` and `PORT` directly and defaults to `0.0.0.0:3000`. A custom Node launcher can use the parsed `server` settings. Restart the service after changes.

## Configuration reference

### Listening

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `server` | Optional object | `{ host: "127.0.0.1", port: 3000 }` | Parsed HTTP listening address and port for a custom launcher. |
| `server.host` | Nonempty string | `"127.0.0.1"` | Hostname or IP address. A nonempty `HOST` takes precedence during parsing. |
| `server.port` | Integer from 1 to 65535 | `3000` | TCP port. A valid `PORT` takes precedence during parsing. |

<a id="local-listening-example"></a>

#### Run a local server

The generated project starts through adapter-node. After building, run `HOST=127.0.0.1 PORT=4100 pnpm start` and open a mounted application route under `http://127.0.0.1:4100`.

With a custom launcher, put the following in `config/_kit.yml` and pass the parsed `server` settings to the HTTP listener. A nonempty `HOST` and a valid `PORT` still take precedence.

```yaml schema=@h-ai/kit:KitConfigSchema
server:
  host: 127.0.0.1
  port: 4100
```

<a id="request-access"></a>

### Trusted proxies and request access

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `http` | Optional object | See the defaults in this section and the rate-limit section. | Trusted proxy, request access, and rate-limit settings. |
| `http.trustedProxies` | `"auto"` or an array of up to 1,000 IPv4/IPv6 addresses or CIDRs | `"auto"` | Accept forwarded addresses only from trusted proxies. `auto` trusts the container subnet on a framework-managed private Compose network. Other deployments ignore forwarding headers by default. `[]` explicitly ignores them. |
| `http.access` | `false`, inline policy object, or separate file object | `false` | Check requests by full path, method, trusted client IP, and time. Inline rules and a file reference are mutually exclusive. |
| `http.access.file` | Path to a regular `.yml` or `.yaml` file, up to 4,096 characters | Required for a file object | Relative to the server process working directory. Read once when assembling the request handler. Maximum file size 1 MiB. |
| `http.access.global` | Inline conditions object | May be omitted | Applies to all requests handled by the current host, including health checks. |
| `http.access.rules` | Array of up to 1,000 path rules | `[]` | A request must satisfy the global conditions and every matching rule. `encryption` can set transport requirements for a matching method and path. |

See the Core request access reference for every field and constraint for time windows, IP lists, paths, HTTP methods, and encryption modes. Serv uses the same policy under `http` in `_serv.yml`. [Core request access](core.en.md#request-access) · [Serv request access](serv.en.md#request-access)

A page data request also checks the access conditions for the corresponding page path. For example, a rule for `/console/reports` also restricts requests for that page’s data.

<a id="trusted-proxy-example"></a>

#### Allow partner networks to read the report

Partners read the orders console’s external report through a reverse proxy. Merge the settings below into `http` in the configuration file for your server. The proxy connects from `192.0.2.10`, and the partner network is `203.0.113.0/24`. Replace both with the addresses used in your deployment.

```yaml schema=@h-ai/kit:KitConfigSchema
http:
  trustedProxies: [192.0.2.10]
  access:
    rules:
      - id: partner-reports
        paths: [/api/v1/external/reports]
        methods: [GET]
        allowIps: [203.0.113.0/24]
```

Request `GET /api/v1/external/reports` through the proxy from the allowed network. Expect HTTP 200. Repeat from another network and expect 403. If the app is mounted below the origin root, put the full prefixed request path in the rule. To restrict probes, add a separate probe rule or a global policy. [Add partner reports](../getting-started/kit.en.md#orders-console-access)

<a id="time-window-example"></a>

#### Let auditors read reports during working hours

Add this rule to `http.access.rules` with the orders console’s deployed report path. The rule allows requests on weekdays in Shanghai from 09:00 until 18:00, excluding the end time. The report route still checks the existing role and permission.

```yaml schema=@h-ai/kit:KitConfigSchema
http:
  access:
    rules:
      - id: report-hours
        paths: [/api/v1/reports/current]
        methods: [GET]
        timezone: Asia/Shanghai
        windows:
          - days: [1, 2, 3, 4, 5]
            start: '09:00'
            end: '18:00'
```

Sign in as an auditor with `reports:read` and request `GET /api/v1/reports/current` inside and outside that window. Expect 200 inside and 403 on a new request outside it. To let operations manage the policy independently, save the policy object in a separate YAML file and reference it with `http.access.file`. [Separate policy files (Chinese)](request-access.md#4-运维人员携带独立-yaml-交付)

<a id="http-rate-limit"></a>

### Fixed-window rate limiting

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `http.rateLimit` | `false` or object | `false` | Limit request frequency by trusted client IP. The server supplies the atomic counter store. |
| `http.rateLimit.windowMs` | Integer from 1 to 2147483647, in milliseconds | `60000` | Fixed window starting at the first counter write. Later requests share the same expiration. |
| `http.rateLimit.maxRequests` | Positive safe integer | `100` | Requests a client can pass through the limiter in one window. Excess requests receive HTTP 429. |

Pass the parsed rate-limit settings and an atomic counter store to the request host. Use an in-memory store for single-process development. For multiple instances, use the same Redis, namespace, window, and request budget. By default, counters use the trusted client IP. Requests with no resolved address share the `unknown` counter. Store failures return HTTP 503. HTTP requests from the same trusted IP share the budget. Ordinary routes, key exchange, and application health endpoints handled by the Hook all count. CORS preflights are exempt.

To give each signed-in account its own quota, supply the rate-limit key in the host code. YAML accepts the window and request limit.

<a id="rate-limit-config-example"></a>

#### Limit requests from one client

Put the following in `config/_kit.yml`. The example allows two requests from the same trusted client in 10 seconds. For a self-managed reverse proxy, put the actual proxy IPs or CIDRs in the same `http` object.

```yaml schema=@h-ai/kit:KitConfigSchema
http:
  rateLimit:
    windowMs: 10000
    maxRequests: 2
```

Use `HAI_KIT_HTTP_RATELIMIT` to replace the whole setting or `HAI_KIT_HTTP_RATELIMIT_WINDOWMS` and `HAI_KIT_HTTP_RATELIMIT_MAXREQUESTS` to override the fields.

Start the orders console and request `GET /api/v1/status` three times from the same source within 10 seconds. Expect 200 and 200 with 1 and 0 requests remaining, then 429. Wait the number of seconds shown in `Retry-After` and verify that the next request returns 200. Use the actual bind address and deployment prefix. [Configuration and startup example](../getting-started/kit.en.md#orders-console-access)

<a id="transport"></a>

### Transport encryption

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `transport` | `false` or object | `false` | The object configures application-layer transport encryption. Supply a server key ring and shared key registry, and configure the key exchange address on clients. |
| `transport.maxPlaintextBytes` | `"auto"` or an integer from 1,024 to 67,108,864 bytes | `"auto"`, 1 MiB for ordinary routes | UTF-8 plaintext limit for ordinary requests and responses. |
| `transport.maxFutureSkewSeconds` | Integer from 0 to 1,800 seconds | `30` | How far the request timestamp can be ahead of the server clock. |
| `transport.maxRequestAgeSeconds` | Integer from 1 to 3,600 seconds | `300` | How long a request is valid from issuance, including transit time. |
| `transport.routePlaintextBytes` | Up to 100 full paths mapped to integers from 1,024 to 67,108,864 bytes | May be omitted | Limits plaintext in both directions for selected routes. Use the actual request path. `*` matches one complete segment. The smallest matching limit applies. |
| `transport.excludePaths` | Array of full paths starting with `/` | `[]` | Excludes these paths and their subpaths from transport encryption. An explicit `encryption: required` path rule takes precedence. |
| `transport.keyExchangePath` | Absolute path from the origin root | `"/api/v1/_hai/key-exchange"` | Public POST endpoint for key exchange. Path segments may contain ASCII letters, digits, `_`, `-`, and `.`. Dot segments, empty segments, trailing slashes, percent escapes, queries, and fragments are invalid. |

When enabled, Kit encrypts mounted contract APIs, `/api/*` under the app base path, and SvelteKit page data requests by default. It exchanges keys through a dedicated HTTPS POST using protocol JSON. When the orders console mounts its reporting contract at `/console/reports`, use that same full prefix to install browser transport. [Encrypt reports under a custom prefix](../function/kit.en.md#kit-custom-contract-transport)

If SvelteKit is mounted at `/console`, explicitly set `transport.keyExchangePath` to `/console/api/v1/_hai/key-exchange`. Generated apps add the build base path where missing in `excludePaths` and `routePlaintextBytes`. Use actual request paths in access rules. [Transport arguments and base path](../function/kit.en.md#host-options) · [Serv key exchange path](serv.en.md#transport)

Serve clients over HTTPS. Managed deployments inject `HAI_CRYPTO_TRANSPORT_SERVERKEYRING` privately on the server. Parse and check the ring at startup before setting up the cache-backed transport registry. The browser receives public client settings such as the exchange path. For multiple instances, use a shared registry and consistent time windows. [Key ring configuration](crypto.en.md) · [Wire up the server and browser](../getting-started/kit.en.md#orders-console-transport)

<a id="transport-example"></a>

#### Give large responses their own transport budget

Put the following in `config/_kit.yml` in a SvelteKit project with Crypto, a shared registry, and client transport enabled. The example assumes the app is deployed under `/console` and exposes a JSON report export and a public probe. Use the actual paths for your instance.

```yaml schema=@h-ai/kit:KitConfigSchema
transport:
  maxPlaintextBytes: auto
  maxFutureSkewSeconds: 60
  maxRequestAgeSeconds: 300
  routePlaintextBytes:
    /console/api/reports/*/export: 8388608
  keyExchangePath: /console/api/v1/_hai/key-exchange
  excludePaths: [/console/api/health]
```

Confirm the browser requests key exchange at `/console/api/v1/_hai/key-exchange` on the same HTTPS origin. Ordinary routes keep the 1 MiB limit. The export route can return more than 1 MiB and up to 8 MiB of UTF-8 plaintext. Test with data below and above the limit, and check the proxy can accommodate encrypted requests.

<a id="cors"></a>

### Cross-origin access

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `cors` | `false` or an object | `false` | An object enables CORS using the response and preflight rules below. |
| `cors.origin` | Full origin string, comma-separated string, or string array | `"*"` | Allows browsers to read responses. List explicit origins for credentialed requests. Wildcards cannot be used with credentials. |
| `cors.nativeOrigins` | Comma-separated origins with `http:`, `https:`, `capacitor:`, or `tauri:` schemes | None | Allows additional origins for native apps. |
| `cors.paths` | Array of full request paths | All requests handled by the host | Each item matches that path and its descendants. Include the deployment prefix. An empty array matches nothing. |
| `cors.methods` | Array of HTTP methods | `[GET, HEAD, PUT, PATCH, POST, DELETE, OPTIONS]` | Tells the browser which methods can be used after preflight. |
| `cors.allowedHeaders` | Array of request header names | `[Authorization, Content-Type, X-Requested-With, X-Hai-Reauthentication, X-Hai-Terminal]` | Lists the headers the browser is allowed to send after preflight. |
| `cors.exposedHeaders` | Array of response header names | `[]` | Lets browser scripts read additional headers. The host also exposes `X-Request-Id` and `X-Trace-Id`. |
| `cors.credentials` | Boolean | `false` | Allows cross-origin requests to carry credentials such as cookies. |
| `cors.maxAge` | Non-negative integer in seconds | `86400` | How long a browser may cache preflight results, subject to browser limits. |

With CORS enabled for the path, the host handles preflight for OPTIONS requests bearing `Origin` and `Access-Control-Request-Method`. It checks request access before returning 204 and the preflight consumes no quota. Other OPTIONS requests follow the application route’s access, rate-limit, and transport rules.

<a id="cors-example"></a>

#### Let the orders console read an API on a separate origin

The console is at `https://console.orders.example.com` and the API is at `https://api.orders.example.com`. Add these fields to the app’s configuration file and substitute the console’s actual origin. These origins share a site, so the browser can send session cookies when their attributes allow it.

```yaml schema=@h-ai/kit:KitConfigSchema
cors:
  origin: https://console.orders.example.com
  paths: [/api/v1]
  methods: [GET, POST, OPTIONS]
  credentials: true
  allowedHeaders:
    - Authorization
    - Content-Type
    - X-Request-Client
    - X-Request-Id
    - X-Hai-Terminal
    - X-Hai-Reauthentication
    - X-Hai-Locale
  exposedHeaders:
    - Retry-After
    - X-RateLimit-Remaining
  maxAge: 600
```

After signing in, use the browser’s Network panel to confirm that API preflights include an `Access-Control-Allow-Origin` matching the console and `Access-Control-Allow-Credentials: true`. When rate limiting is enabled, the console can use `response.headers.get("Retry-After")` on an HTTP 429 to show when another request can be sent. With application-layer transport encryption, add `X-Client-Id`, `X-Encrypted`, and `X-Hai-Transport` to the allowed request headers used by your client, and expose `X-Encrypted` and `X-Hai-Transport`.

<a id="cors-multipart"></a>

#### Allow a trusted console to upload order attachments

Production SvelteKit checks the Origin of cross-origin form requests before calling `kit.createHandle()`. An OPTIONS preflight can succeed while the upload returns HTTP 403 if SvelteKit's `csrf.trustedOrigins` omits the calling origin. This list applies to the application's form submissions. Use `cors.paths` to scope Kit's CORS handling.

In the orders API's `vite.config.ts`, merge this field into the existing `sveltekit({...})` options and rebuild. If your application uses `svelte.config.js`, put the same `csrf` object under `kit`. List the complete HTTPS origins of trusted pages.

```ts
sveltekit({
  csrf: { trustedOrigins: ['https://console.orders.example.com'] },
})
```

Configure CORS for the attachment route in `config/_kit.yml`. If you also use application-layer transport encryption, the request rule below allows this multipart POST over HTTPS. Pass `http` and `cors` to `kit.createHandle()`, and mount the upload operation with a request body limit and file ownership authorization. [File transfer setup](../function/serv.en.md#storage-transfer-procedures-api)

```yaml schema=@h-ai/kit:KitConfigSchema
http:
  access:
    rules:
      - id: order-attachment-upload
        paths: [/api/v1/storage/files/upload]
        methods: [POST]
        encryption: disabled
cors:
  origin: https://console.orders.example.com
  paths: [/api/v1/storage/files/upload]
  methods: [POST]
  allowedHeaders: [Authorization, Content-Type]
```

Call this function from the console with the Bearer token acquired at sign-in, a server-authorized object `key`, and a user-selected `file`. The browser sets `Content-Type` with its multipart boundary.

```ts
async function uploadAttachment(file: File, key: string, accessToken: string) {
  const body = new FormData()
  body.set('key', key)
  body.set('file', file)
  return fetch('https://api.orders.example.com/api/v1/storage/files/upload', {
    method: 'POST',
    headers: { Authorization: `Bearer ${accessToken}` },
    body,
  })
}
```

Verify on the production build over HTTPS that OPTIONS returns 204, an authorized upload returns `success: true`, and a form POST from another origin returns 403. For an origin without CORS permission, check the API's HTTP response in the Network panel or server logs.

<a id="cookie-encryption-example"></a>

#### Encrypt an application preferences cookie

Initialize Crypto in `hooks.server.ts` and add the application's order preferences cookie, `order_preferences`, to `crypto.encryptedCookies`. Use the existing cookie name in your app. The command below uses OpenSSL to generate a local test key. Start the built app in the same shell. [Hook example for the order preferences cookie](../function/kit.en.md#orders-console-cookie)

```bash
export HAI_KIT_COOKIE_KEY="$(openssl rand -hex 16)"
pnpm start
```

Save an order preference. In the browser’s Network panel, check that the URL-decoded `order_preferences` value in the `Set-Cookie` response header starts with `enc:v2:`. Reload the page and check that the application reads the saved preference. In production, inject a stable key from your server-side secret store and use the same key on all instances in the environment.

<a id="a2a"></a>

### A2A HTTP endpoints

| Field | Type and constraints | Default | Purpose |
| --- | --- | --- | --- |
| `a2a` | `false` or an object | `false` | Sets the public A2A discovery and message paths. The application also supplies the initialized handler. |
| `a2a.cardPath` | Site-absolute path | `/.well-known/agent-card.json` | GET route that returns the public Agent Card. |
| `a2a.rpcPath` | Site-absolute path distinct from `cardPath` | `/a2a` | POST route for authenticated JSON-RPC requests, including operations that return SSE. |

#### Let a partner’s program review the order backlog

Publish the orders assistant on a dedicated URL. Use the actual request paths and configure the reverse proxy to forward them to the host that mounts the handler.

```yaml schema=@h-ai/kit:KitConfigSchema
a2a:
  cardPath: /.well-known/agent-card.json
  rpcPath: /partners/orders/a2a
```

Set the Agent Card URL in `_ai.yml` to `https://api.orders.example.com/partners/orders/a2a` and declare `X-Agent-Key` as the header in `a2a.security.apiKey`. At startup, initialize AI and IAM, register the orders assistant executor, and mount the HTTP handler. Pass the issued partner key through `ORDERS_AGENT_KEY`. Serve both endpoints over HTTPS without application-layer transport encryption. [A2A](../function/ai.en.md#a2a)

```sh
orders_origin=https://api.orders.example.com
curl --fail-with-body -sS "$orders_origin/.well-known/agent-card.json"
curl --fail-with-body -sS "$orders_origin/partners/orders/a2a" \
  -H "X-Agent-Key: ${ORDERS_AGENT_KEY:?}" \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":"orders-backlog-1","method":"SendMessage","params":{"message":{"messageId":"orders-backlog-1","role":"ROLE_USER","parts":[{"text":"Summarize the order backlog."}]}}}'
```

Discovery returns the advertised JSON-RPC address. A successful call returns a JSON-RPC `result`. A missing or invalid key returns HTTP 401. For a subdirectory deployment, include the mount directory in both configured paths.

## Apply and verify

After restarting, check authentication cookies and application routes from the same domain users visit. Verify the trusted address reported by the proxy, denial responses for requests that fail the policy, and the key exchange when transport encryption is enabled.
