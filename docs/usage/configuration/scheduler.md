# Scheduler 配置

[配置手册](README.md)

## 配置入口

生成项目使用 `config/_scheduler.yml`，配置注册名为 `scheduler`，环境覆盖前缀为 `HAI_SCHEDULER_`。覆盖顺序和无敏感值示例见[运行配置](runtime.md#配置从哪里来)。

`scheduler.init(config)` 使用 `SchedulerConfigSchema`。调度器需要已初始化的 RelDB；多节点部署时使用共享的同一数据库。Cron、时区、任务处理器和可选的执行超时由宿主注册任务时提供。向 `scheduler.init()` 传入的运行时对象也可包含 `tasks`（启动时登记的任务）或 `hooks`（全局生命周期钩子）。

## 配置示例

```yaml schema=@h-ai/scheduler:SchedulerConfigSchema
tickInterval: 1000
leaseMs: 300000
nodeId: orders-scheduler-east
retentionDays: 30
```

## 配置清单

表中的默认值适用于当前配置区块存在时。标为“必填”的字段在使用对应区块或后端时填写。“可省略”表示 Schema 不填充值；如有运行时回退，单独注明。`[]` 表示数组中每一项。

| 配置项          | 默认值/必填         | 说明                                                                                               |
| --------------- | ------------------- | -------------------------------------------------------------------------------------------------- |
| `enableDb`      | `true`              | 必须使用共享数据库保存执行状态；false 不再允许，需要先初始化。可填`true`                           |
| `tickInterval`  | `1000`              | 调度检查间隔，单位毫秒。至少 100 的整数                                                            |
| `leaseMs`       | `300000`            | 执行租约毫秒数（默认 300000，范围 1000–86400000），在途每三分之一周期续期。可填整数，1000–86400000 |
| `nodeId`        | 由宿主进程生成 UUID | 部署中的节点标识，用于租约及问题定位。可填字符串，至少 1 个字符                                    |
| `maxLogs`       | 不按条数清理        | 配置后限制保留的执行日志条数。至少 1 的整数                                                        |
| `retentionDays` | 不按天数清理        | 配置后仅保留该天数内可清理的执行日志。至少 1 的整数                                                |

## 生效与核对

修改租约时核对执行续租和未知状态处理；中断调度器可能使外部副作用结果未知。清理配置只影响可清理的执行记录。多节点示例见[租约、时间与未知执行](operations.md#scheduler租约时间与未知执行)。
