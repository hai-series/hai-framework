# @h-ai/feedback 設定

[简体中文](feedback.md) · [English](feedback.en.md) · [API リファレンス](../function/feedback.ja.md) · [データ構造](../data/feedback.ja.md)

## 設定の読み込み

アプリのサーバー側の設定ディレクトリに `config/_feedback.yml` を置きます。管理コンソールは起動時に Core でファイルを読み込み、`FeedbackConfigSchema` で検証します。独自に組み込む場合は RelDB に接続してから `feedback.init(config)` を呼びます。初期化の成功後に API で送信や参照ができます。アプリ ID、送信や収集の上限、保存期間を変更した後は Feedback を実行しているサービスを再起動します。

<a id="configuration-fields"></a>

## 設定一覧

**`appId`** は必須です。初回投稿の `app_id` に保存され、一覧、詳細、メッセージ、添付ファイルの参照をこのアプリに限定します。

前後の空白を除いて 1〜128 文字の文字列を指定します。NUL は使用できません。環境変数は `HAI_FEEDBACK_APPID` です。

同じデータベースを使う別々のアプリには異なる `appId` を設定します。同じアプリの複数インスタンスがデータベースを共有する場合は同じ値を使います。たとえば `orders` と `inventory` はテーブルを共有しながら個別のフィードバック一覧を持てます。`orders` を `orders-v2` に変えると、新しいインスタンスは新しい ID で検索し、既存のレコードは `orders` に属したままです。

### 送信の上限

初回投稿、返信、情報追加の依頼は、送信ごとに以下の上限で検証します。設定には整数を指定し、省略時は既定値が使われます。ファイルサイズは Base64 への変換前のバイト数で計算します。

- **`limits.maxBodyLength`** 1 回の送信で入力できる本文の長さです。UTF-16 のコード単位で数え、たとえば「問題😀」は 4 コード単位です。ファイルだけを送る場合はフォームの本文を空欄にします。API を直接呼ぶ場合は `body` に空文字列を渡します。

  既定値は `5000`、設定範囲は `1`〜`20000` です。環境変数は `HAI_FEEDBACK_LIMITS_MAXBODYLENGTH` です。

- **`limits.maxFiles`** 1 回の送信で手動で追加できるファイル数です。画像を含め、手動で選んだファイルを 1 件ずつ数えます。

  既定値は `5` 件、設定範囲は `1`〜`20` です。環境変数は `HAI_FEEDBACK_LIMITS_MAXFILES` です。

- **`limits.maxFileBytes`** ファイル 1 件あたりのサイズ上限です。手動の添付ファイルと初回投稿の資料を、ファイルごとに確認します。

  既定値は `5242880` バイト（5 MiB）、設定範囲は `1`〜`10485760` バイトです。環境変数は `HAI_FEEDBACK_LIMITS_MAXFILEBYTES` です。

- **`limits.maxTotalFileBytes`** 1 回の送信で使えるファイルサイズの合計です。初回投稿では、手動の添付ファイルと送信するスクリーンショット、ブラウザーログ、操作リプレイ、録画を合計します。返信や情報追加の依頼では、その送信の添付ファイルを合計します。

  既定値は `10485760` バイト（10 MiB）、設定範囲は `1`〜`25165824` バイトです。1 ファイルの上限以上に設定します。環境変数は `HAI_FEEDBACK_LIMITS_MAXTOTALFILEBYTES` です。

標準フォームは本文の入力長を制限し、ファイルの選択時や送信時に上限を超えるとエラーを表示します。API を直接呼ぶ場合も、サービスは上限を超えた送信を拒否します。

たとえば、初回投稿に 4 MiB の画像 2 枚を手動で添付し、3 MiB の録画を追加する場合を考えます。手動添付は 2 件で、各ファイルは既定の 5 MiB 以内です。合計は 11 MiB になり、既定の 10 MiB を超えます。録画を外すと、残りの 8 MiB を送信できます。

サーバーログの追加を選ぶと、サービスは初回投稿の残り容量に収まる最近のログを取り出します。1 件も収まらなければ、ログファイルを省略します。

### 初回投稿の資料

初回投稿に含められる資料の量を設定します。省略した項目は既定値になります。ログと操作リプレイには、それぞれのサイズ上限と 1 ファイルの上限のうち小さい方が適用されます。これらのファイルも送信時の合計サイズに含まれます。

- **`capture.windowSeconds`** 資料をどこまでさかのぼって取得するかを指定します。ブラウザーログと操作リプレイはダイアログを開いた時点、追加を選んだサーバーログは初回投稿の送信時点が基準です。

  既定値は `300` 秒（5 分）、設定範囲は `1`〜`1800` 秒です。環境変数は `HAI_FEEDBACK_CAPTURE_WINDOWSECONDS` です。

- **`capture.maxLogEntries`** ログファイル 1 件に入れるログの件数です。ブラウザーとサーバーのログは別々に数え、新しいログを優先します。

  既定値は `1000` 件、設定範囲は `1`〜`5000` 件です。環境変数は `HAI_FEEDBACK_CAPTURE_MAXLOGENTRIES` です。

- **`capture.maxLogBytes`** ログの JSON ファイル全体のサイズ上限です。ログの各項目が長い場合は、件数の上限より先にこの上限に達することがあります。

  既定値は `524288` バイト（512 KiB）、設定範囲は `1`〜`2097152` バイトです。環境変数は `HAI_FEEDBACK_CAPTURE_MAXLOGBYTES` です。

- **`capture.maxReplayBytes`** 操作リプレイの JSON ファイルのサイズ上限です。ページ全体のスナップショットとそれに続く操作が一つの区間です。上限を超えると、ブラウザーは古い区間から破棄します。

  既定値は `2097152` バイト（2 MiB）、設定範囲は `1`〜`8388608` バイトです。環境変数は `HAI_FEEDBACK_CAPTURE_MAXREPLAYBYTES` です。

- **`capture.maxReplayEvents`** 操作リプレイ 1 件あたりのイベント数の上限です。ページ全体のスナップショット、ビューポート情報、クリックなどの操作を数えます。上限を超えるとスナップショットごとの区間を破棄します。

  既定値は `2000` イベント、設定範囲は `1`〜`10000` です。環境変数は `HAI_FEEDBACK_CAPTURE_MAXREPLAYEVENTS` です。

- **`capture.maxRecordingSeconds`** 利用者が許可し、ブラウザーで録画を開始してからの最長時間です。時間に達するか、ファイルサイズが上限に近づくと録画を停止します。サービスはアップロードされた録画のサイズと形式を検証します。

  既定値は `60` 秒、設定範囲は `1`〜`300` 秒です。環境変数は `HAI_FEEDBACK_CAPTURE_MAXRECORDINGSECONDS` です。

### 保存期間

- **`retention.days`** 最後の更新からフィードバックを参照できる日数です。初回投稿時点から数え、新しいメッセージや状態の変更があるたびに起算点を更新します。`0` で無期限になります。

  既定値は `0`、設定範囲は `0`〜`3650` 日です。環境変数は `HAI_FEEDBACK_RETENTION_DAYS` です。

たとえば `90` に設定すると、返信した時点から 90 日後が新しい期限になります。状態にかかわらず、期限を迎えると直ちに一覧と詳細から参照できなくなります。サービスは起動時と毎時、そのアプリの期限切れの投稿とメッセージ、添付ファイルを分割して削除します。同じアプリのインスタンスでは同じ設定を使います。再起動後は既存の投稿にも新しい設定が適用されます。 [データの保持](../data/feedback.ja.md#retention)

## ホストへの組み込み

ホストは次の設定でデータベースに接続し、権限と業務スコープを決定してファイル転送を構成します。

| 層 | 設定場所 | 適用されるタイミング |
| --- | --- | --- |
| データベース | `reldb.init` に渡す接続設定。管理コンソールは `config/_db.yml` を読み込みます。 | Feedback の起動後、ホストが選んだ SQLite、PostgreSQL、MySQL のいずれかに 3 テーブルが用意されます。 |
| 利用者と業務スコープ | ホストは `resolveContext` で信頼できるセッションから `userId`、`scopeId`、権限を渡します。Core ログを関連付ける場合、業務リクエストの Core コンテキストにも同じスコープを設定します。 | API リクエストごとにセッションとスコープで権限を確認します。ロールの割り当てはホストが管理します。 |
| ブラウザーの資料 | ホストがログイン済みの `FeedbackModal` に `captureKey` を渡し、`getLimits` でサービスの設定を読み込みます。投稿者は資料の確認・削除、録画の許可、サーバーログの追加を選べます。 | コンポーネントは上限を読み込んでからページ内の記録を開始します。ダイアログを開いた時点で、最近のブラウザーログと操作リプレイを確定します。利用者の選択はその送信に適用されます。 |
| HTTP トランスポート | Kit の `_kit.yml` または Serv の `_serv.yml` で `transport` を管理します。暗号化が有効な場合は `transport.routePlaintextBytes` でファイルを扱うルートの容量を宣言します。 | ホストが HTTP リクエストとレスポンスの容量をルートごとに検査します。 |
| 保存期間 | `_feedback.yml` の `retention.days` | 期限の過ぎた投稿は参照できなくなり、サービスが分割して削除します。 |

## 設定例

### 固定のアプリ ID を設定する

注文アプリの `config/_feedback.yml` に次の内容を書き、先にデータベースへ接続します。

```yaml schema=@h-ai/feedback:FeedbackConfigSchema
appId: orders
```

起動後にフィードバックを送信すると、データベースの `hai_feedback_reports.app_id` で `orders` を確認できます。注文アプリの「自分のフィードバック」からその投稿を開きます。管理コンソールも同じ方法で `appId: admin-console` を使います。

### 環境ごとにアプリ ID を指定する

Core が `feedback` 設定を読み込むとき、`HAI_FEEDBACK_APPID` はファイルの `appId` に優先します。前の例の固定値も上書きできます。別の環境で `HAI_FEEDBACK_APPID=orders-staging` を設定して再起動すると、その環境の新規投稿は `orders-staging` に属します。

CLI テンプレートでは環境変数のプレースホルダーも記述し、生成先のプロジェクト名を代替値に使います。注文アプリの設定ファイルは次のようになります。

```yaml schema=@h-ai/feedback:FeedbackConfigSchema
appId: ${HAI_FEEDBACK_APPID:orders}
```

環境変数を設定しなければ、この例では `orders` が使われます。ファイルで指定した代替値であり、`appId` 自体に既定値はありません。 [Core の環境設定](core.ja.md)

### 容量と保存日数を変更する

たとえば注文アプリのサポート担当者が、利用者から 1 回の返信で 6 MiB のファイルを 2 件受け取り、最後の更新から 90 日間フィードバックを保持する場合の設定です。この例では、初回投稿の資料をさかのぼる時間を 3 分間、録画を最長 45 秒とします。省略した項目は既定値になります。

```yaml schema=@h-ai/feedback:FeedbackConfigSchema
appId: orders
limits:
  maxFileBytes: 6291456
  maxTotalFileBytes: 12582912
capture:
  windowSeconds: 180
  maxRecordingSeconds: 45
retention:
  days: 90
```

変更後は Feedback のサービスを再起動し、ページを更新します。ホストは認証済みの `GET /feedback/limits` から `limits` と `capture` を取得し、投稿と会話の入力欄で使えます。縮小した上限は新規送信に適用し、既存の投稿と添付は期限まで取得できます。

<a id="transport-budget"></a>

### ファイル用ルートの平文容量

ホストでトランスポート暗号化を有効にする場合、`apiContract.feedbackTransportRoutes(apiPrefix, maxTotalFileBytes)` を `transport.routePlaintextBytes` にマージします。プレフィックスには実際のマウント先を渡します。Kit の `/api` や、`/console` 配下へデプロイする場合の `/console/api` が例です。`/api` の場合、補助関数は次のルールを生成します。既定では 16 MiB です。合計の上限を引き上げると投稿とメッセージの容量枠も増えます。添付の読み込みは既存ファイルに対応する 16 MiB のままです。

| パス | 対象 |
| --- | --- |
| `/api/feedback/reports` | 初回投稿と資料の送信。 |
| `/api/feedback/reports/*/messages` | 返信、情報追加の依頼とそれらの添付ファイルの送信。 |
| `/api/feedback/reports/*/attachments/*` | 個別ファイルを Base64 で取得。 |

10 MiB のファイルを Base64 に変換すると約 13.33 MiB になり、JSON とトランスポートの包みによる増分も発生します。実際の `limits.maxTotalFileBytes` を渡すと、シリアライズ済みデータに対応する平文枠を計算できます。ファイルの上限は元のバイト数で計算します。リバースプロキシやホスティング環境に別のリクエストサイズ制限があれば、エンコード済みリクエストを通せるようにします。管理コンソールはフィードバック用ルートの既定値を読み込んだ後、ホストが明示したルートの値を適用します。
