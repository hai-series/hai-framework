# 安全审查与恢复条件

[维护与验收](README.md) · [安全审查路线](../overview/reading-paths.md#安全审查人员沿请求凭据和副作用查边界)

沿一次实际业务操作检查信任边界。先确定谁发请求、服务端如何识别身份、会修改哪些状态、外部动作能否确认，再判断风险；不把所有技术差异都写成漏洞。

## 请求、身份和资源范围

按[身份配置](../configuration/identity.md)核对登录/注册、会话、账号锁定、二次认证和权限，按[HTTP边界](../configuration/http.md)核对可信代理、Cookie、CORS和传输。使用普通用户、跨用户资源ID、受限API Key和重放请求验证服务端拒绝；按钮隐藏和CORS不代替授权。

二次证明绑定当前用户、会话和用途并单次消费，取消不发送业务请求。原生终端标识不是硬件证明，客户端自报地址不是可信IP。

## 输入、材料和隐私

入口Schema验证类型/范围；SQL值参数化，标识符白名单；文件路径防逃逸，私有对象经授权签名。上传、加密、代理和导出预算一致，超限明确拒绝而非截断成功。

检查日志、URL、错误、截图和反馈包是否保留秘密。默认凭据脱敏不能识别任意无标签秘密；业务隐私字段显式配置，截图敏感区域标记并允许提交前删除。公开错误保留安全消息/traceId，排查图标按需显示编号，不公开堆栈、SQL或密钥。

## 并发、超时和外部副作用

使用[共享数据配置](../configuration/data.md)和[任务边界](../configuration/operations.md)核对CAS、租约、稳定幂等键和最终提交。获取锁或续租成功不证明通知/支付只执行一次。

超时/断连的外部结果可能unknown，先按业务ID核对，不自动重试非幂等动作。反馈身份关闭先等待在途请求，不继续旧草稿后续操作；已发请求不能承诺撤销。

## 生产发布与回退

按[部署恢复](../configuration/delivery.md)检查受管凭据和卷成套备份、旧完整制品、匹配配置与数据兼容。拒绝在原卷原地切DB/存储/向量引擎，缺状态不随机换密。自动旧容器启动后仍验旧端口/健康，不能只凭compose成功。

容器/配置回退不恢复业务数据、Schema或已完成的外部动作；零停机/蓝绿也不属于当前Compose承诺。强杀、断电和远端unknown需人工核对真实状态。

## 形成可执行发现

每项写清问题、触发场景、影响、建议、源码/运行证据和验证条件。区分配置不满足目标环境、已确认实现缺陷和缺现场证据的推测。目标服务没有实测时写明边界，不以Schema、Mock或单机成功扩大生产结论；证据范围见[验证说明](verification.md)。
