# Skills 与界面改进问题清单

本轮目标：让需求、实现、审查和验收接得起来，让业务应用能用同一套 Hai 组件做出清楚、好用的界面。先记录问题，再逐项修正；每项通过对应验证后才关闭。

优先级：P1 表示会影响正确交付或基本操作，P2 表示会影响一致性、可理解性或使用体验。下表保留修改前的问题，修正结果与本地验收见后文。

## 执行顺序

实施期间主分支合入三语支持，后续模板验收又发现声明构建问题，补充以下三项；保留主分支变更并在新基线上复验。

| 编号 | 优先级 | 问题及影响 | 修改位置与验收 | 状态 |
| --- | --- | --- | --- | --- |
| V01 | P1 | 三语消息检查把 CLI 临时生成工程也当作源码，导致读取不存在的日文文件；本轮新增文案也需同步新加入的日文。 | 消息扫描排除临时/构建/证据目录，加入目录发现用例；UI 与展厅三语键和插值一致。 | 已修正并验证 |
| V02 | P2 | 新合入的日文 CLI 提示在 60 列终端中自动折行，prompts 清除行数不足，重绘残留文字。 | 帮助提示单独换行并按显示宽度排版；中日文 60/80/120 列真实提示重绘用例通过。 | 已修正并验证 |
| V03 | P1 | fullstack 生成工程的共享接口声明无法构建，后续应用验证无法继续。 | `@h-ai/api-contract` 公开转出声明推导所需的上游类型；同步 API 清单、README 和 skill，隔离安装后的声明构建与完整流程通过。 | 已修正并验证 |

1. S01：统一名称和入口。
2. S02–S05：完善 SDD 交接、审查与证据规则。
3. U01–U06：先增加能复现问题的行为用例，再修正共享组件和样式。
4. F01–F03：补齐前端设计/审查技能，落到示例、CLI 与文档。
5. 收集相关门禁，归并失败原因后集中修复，再复测失败和受影响项；实际浏览器走查并保留截图。

## 命名规则

工作流统一使用 `hai-领域-动作`，例如 `hai-app-create`、`hai-app-review`、`hai-module-create`、`hai-module-review`、`hai-spec-review`、`hai-ui-design`、`hai-ui-review`。能力使用类沿用包领域名：`hai-ui`、`hai-ai`、`hai-iam`、`hai-reldb`。仓库入口与 CLI 模板可面向不同读者，但共享名称和公共契约。

## 本地验收与边界

2026-10-23，Windows、Node 24.18.0、pnpm 12.11.2、Chrome 157.0.8103.15。验收基于 `05c2cb5d84a8a67d298af1f8638425115a07ecac` 加本轮提交前的工作区快照；实现按下列任务分组提交。运行门禁期间源码指纹保持一致，收尾仅更新问题清单、设计说明与生成的 API 清单。

- 受影响 UI、CLI、api-contract、admin-console 的 typecheck/lint 通过；24 项框架包和示例构建通过。
- 1,117 项单元测试、89 项脚本测试通过。CLI 另有 42 项专项用例按原有开关跳过，脚手架专项另行运行。
- `check:skills`、`generate:api`、`check:api` 与公开入口 `test:api` 通过；公开入口覆盖 21 个包导入和 30 个浏览器入口。
- 37 项实际 Chrome 用例通过，覆盖本地 IAM 增改删、表单、展厅、设置和新交互示例；三语、明暗主题、触摸及减少动态效果均验证。中文检查 390/1440/1920/2560/3840px，英文和日文检查 390/1440px。
- 八类 CLI 生成工程的隔离安装与适用门禁通过：api、admin、api-iam、api-iam-basic、website、h5、mobile-app、fullstack。

日志、源码指纹、手工回放和截图保存在本地忽略目录 `tmp/skills-ui-validation/` 与应用 `test-results/`，不提交验收产物。展厅使用受控数据；本地 IAM 流程使用隔离后端，通知使用 fixture。浏览器结果不代表真机、原生宿主或真实外部 Provider 验收。本轮包含 UI 交互、共享样式与 CLI 交付逻辑的运行时代码变更。
