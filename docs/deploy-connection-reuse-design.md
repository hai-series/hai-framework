## 连接与配置行为

1. 支持既有私钥/SSH agent 和新增密码方式。SDK 使用可选 `ssh.auth`（`key` / `password`）和 `ssh.password`；未指定 auth 时，有密码使用密码，否则保留 key/agent。显式 key 不受残留密码干扰；显式 password 缺值失败。
2. CLI 首次补齐缺失字段，密码输入不回显且保留前后空格。后续有效配置直接复用；完整非交互配置不再询问。用户仍可选择本次环境、服务及中间件处理范围。
3. 支持在默认未声明 ssh 节点时，由已知 SSH 叶级环境变量补齐该节点；只接受现有 Schema 字段。父对象与叶覆盖遵守来源优先级，同一来源中更具体字段优先。密码等文本不因 YAML 解析丢失空格或前导零。
4. 新保存的私有连接、密码和中间件凭据放在选中环境的 `.env.<environment>.local`，公共配置保留在 `.env.<environment>`。保留旧 `.env.local` 的兼容读取，不自动猜测归属、不删除无关值；所选环境已明确的部署目标不得被旧全局目标压过。进程显式覆盖最高。
5. 已完整配置的中间件在 `--yes` 下保持，不重新输入、不重复云开通；既有自建凭据继续稳定复用，损坏状态失败而非悄悄重置。

## 执行与离线交付

1. 保留 OpenSSH 的主机键校验、受控命令、流式脱敏、背压、超时及子进程退出核验。密码通过 SSH_ASKPASS 和本次子进程环境传递，不进入命令参数或 helper 源码。
2. Windows 使用系统 Windows PowerShell 5 编译不含密码的固定原生 helper；POSIX 使用私有 shell helper。失败时返回明确错误，不静默降级认证或主机校验。准备 helper 计入原超时预算，并只清理本次资源。
3. 按实际 OpenSSH readpass 边界保留密码原值，拒绝 CR/LF/NUL，UTF-8 最多 1023 字节。错误、日志、结果与回调均不得泄露密码。
4. `deploy-target.json` 保存连接参数、认证方式和密码环境变量名称，不保存密码值。默认引用 `HAI_DEPLOY_PROVIDER_SSH_PASSWORD`；操作机配置一次本机环境后可重复上传。SSH 密码不得进入应用环境、tar、manifest 或公开 target JSON。
5. `deploy.sh` 与 `deploy.ps1` 均支持两种认证；继续无 Node/pnpm 依赖。`deploy-local.sh` 在服务器本地执行，不需要 SSH。修改某包 target 只影响本包，不反向修改工程；新包从已保存的工程配置生成。
