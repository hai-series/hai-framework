## PostgreSQL 验证

先运行 Runner 的真实容器回归。变更前节点不会等待同一个结构锁，同名表还会让索引创建静默跳过。改用 RelDB 的事务结构准备后，三个独立进程在同一 PostgreSQL 上等待并完成空库和旧库初始化。故意制造索引名冲突会回滚当次创建的 Runner 表，移除冲突后同一实例可以重试。旧库测试保留升级前提交的任务。

Audit 的留存设置、Feedback 的配额表和 IAM 的角色关系表也有多步表与索引初始化。它们统一使用表级名称校验和事务准备，启动失败时回滚已做的结构变更。真实 PostgreSQL 回归覆盖空库、并发等待、旧索引冲突、失败重试和写入不被再次初始化阻塞。Feedback 和 Audit 的现有 MySQL 路径也通过回归。

Scheduler、Reach、Payment、IAM 基础表和 Audit 日志表沿用 RelDB 的独立建表操作及冲突重试。AI 已有自身事务迁移。Crypto 惰性建表后用唯一键执行写入。Agent 自己的表和索引在 `prepareSchema` 中准备，真实验收使用两个 Web 节点和两个执行节点同时从空库启动。

## 浏览器验收

| 场景 | 验收结果 |
| --- | --- |
| 自动和个人 Worker | 真实 Codex 通过 Responses 网关完成任务，自动选出个人 Worker，切换 Web 节点后继续读取结果。另一个账号读取该任务返回 404 |
| 共享 Worker | 两个登录的主体通过官方 DeepSeek Chat 共用同一个 DeepSeek Harness 进程，各自收到私有会话结果。原生模型请求中工具清单为空 |
| 独占 Worker、审批与 Git | DeepSeek Harness 请求写入测试工程。用户批准一次后完成改动，浏览器显示私有补丁。再次确认后只向测试远端推送独立的 `agent/` 分支 |
| 工具与资料 | 原生 DeepSeek 调用登记的 MCP 测试工具并显示状态，原生 Codex 查到真实 Qdrant 中的资料并显示片段和来源。测试使用固定 Embedding 以便复现检索 |
| 语音、个人资料和文件 | MiMo 生成 WAV 并转写。浏览器回归验证 IAM 登录登出、偏好保存、记忆编辑、资料归属、私有文件和同源写入 |

生产环境使用受信部署的对象存储和模型中继。四节点浏览器验收在同一宿主机上运行，共用 PostgreSQL、Redis、Qdrant 和 RustFS S3。同账号可从另一 Web 节点下载工具产物，其他账号访问返回 404。

中文验收复现了 PostgreSQL 读取 JSONB 后字段顺序变化导致授权列表漏项的问题。修正后，执行节点批准的规则可在另一个 API 进程查询和复用。真实 PostgreSQL 回归验证了 API 进程退出后规则仍可读取，另一个账号无法查看或撤销，撤销后已有会话也不会再使用该规则。

切换任务时会清空草稿和临时引用。浏览器回归验证了附件不会带到下一任务，新任务应用保存的记忆默认值，异步上传和语音结果按发起任务的观察状态处理。长中文历史按 Token 预算保留最近消息的摘录。真实 Codex 验收从长消息触发压缩，随后提交下一轮成功。中文录屏包含知识索引、技能引用、流式 Markdown、语音、工具和授权等操作。冷启动与资源样本见[工作台接入文档](usage/development/agent.md#冷启动回复速度和资源实测)。
