# 应用审查

## 能力契约

| 项目 | 契约 |
| --- | --- |
| 能力 | 审查 hai 应用的路由、权限、i18n、服务层与交互体验 |
| 适用场景 | 用户要求应用代码/体验审查或修复评估 |
| 输入 | 用户指定范围、代码/差异、运行证据与验收要求 |
| 输出 | 按优先级列出的证据、影响和修正建议 |
| 限制 | 只读审查不自动改代码；未读取的实现不下结论，不把偏好当缺陷。实现修复需用户已授权。 |

## 使用路径

1. 读取用户需求、差异、实际应用架构和验收场景；保留已有改动，只读审查不自动扩展为修复。
2. 按共享应用审查路径追踪输入、权限、服务、副作用和 UI，不把模板默认业务当作不可修改的需求。
3. 框架源码内应用另按本仓库规范验证；公共变更同步示例、CLI 模板、文案与文档。
4. 按优先级报告具体位置、复现证据、影响与验收方式；已有修复授权时完成修正和验证。
