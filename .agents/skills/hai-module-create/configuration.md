# 配置、环境变量与消费点对应表

本表覆盖 22 个框架包。每个可通过 YAML 配置的字段，其单位、枚举及数值限制以[环境变量总表](../../../.env.example)和[CLI 配置目录](../../../packages/cli/src/commands/cli-config-catalog.json)为准；两者由实际公开 Schema 生成；赋值是供选择的示例建议值，必填枚举的首项不表示 Schema 有默认值。真实解析默认值以对应 Schema 的 default 及消费者父对象默认值为准，不另维护一份手写默认值。复杂的跨字段、Provider 和生产限制须同时阅读下面列出的实际消费点与模块说明。

纯配置消费者可从 `@h-ai/reldb/schemas` 导入同一组数据库 Schema/类型；该入口只依赖 Zod，不创建实例或加载驱动。CLI 部署向导内联它，并在保存连接前按实际后端校验 TLS。

LLM 请求协议使用 `llm.protocol`、`llm.models[].protocol` 和 `tempModel.protocol`；对应 `HAI_AI_LLM_PROTOCOL`、`HAI_AI_LLM_MODELS_0_PROTOCOL` 等。旧 `api` 字段及旧协议变量必须明确报告迁移错误，不能忽略后回退。密钥字段 `apiKey` 不变。环境目录保留完整 Schema，面向用户的 `.env.example` 优先列细项，避免同时推荐冗余父 JSON；`false | 对象` 开关及无固定子键的动态映射仍保留。

## 配置经过哪些步骤

1. `core.config.loadEnvFiles` 读取公共基础、环境及本机私有文件，返回合并结果；调用方决定是否注入进程。已有进程环境优先，空字符串也是显式覆盖。不要在环境总表中填入真实凭据。
2. `core.init({ configDir })` 扫描运行时 YAML；构建部署配置独立放在项目根 `hai.json`，Core 不为特定 YAML 文件名设置例外。只有 `_core.yml` 自动用 Core Schema 校验，其它运行时 YAML 先进入配置缓存；单项加载返回失败时记日志并继续，目录扫描等异常仍可能传播。应用必须 validate 必需配置并检查 success，再交给对应模块 `init` 或工厂/适配器，不能把“文件已加载”等同于“模块已初始化”。
3. 约定变量为 `HAI_<配置名>_<路径>`，camelCase 不拆词；数据库配置名是 `db`，所以是 `HAI_DB_*`。同来源父 JSON 为基础，细项继续覆盖，与行序无关；高来源整体替换先清掉低来源细项。宿主显式提供模块 Schema 时可识别 YAML 缺少的合法路径，无 Schema 则按已有结构。数组 JSON 保留，索引只更新已有元素，越界报错；不能把索引当作固定 Provider。
4. 初始化 Schema 填充默认值并检查字段；后端连接/资源就绪成功后才发布实例。关闭按依赖反序执行并检查结果。纯函数、客户端工厂、serv 和 kit 按自身公开契约使用，不能套用服务端生命周期。
5. `pnpm generate:env` 在依赖包 fresh build 后更新总表与应用示例，`pnpm check:env` 检查生成一致性；`check:skills` 检查 skill 契约。它们不证明字段已传入 SDK、共享状态正确或真实投递成功，仍须验证对应消费者及真实后端行为。

入口扫描按 TypeScript AST 边界排除 JS/TS 与 Svelte script 中的真实 JSDoc，不删除字符串、正则或插值模板正文；Schema 字段说明仍从原始注释读取，YAML/生成模板的可选字段引用继续收集。

## 跨模块配置约束

- Serv/Kit 的 transport.maxPlaintextBytes 支持显式 1 KiB～64 MiB 整数或 auto；auto 解析为 undefined。宿主将反馈预算作为 requiredPlaintextBytes 交给 crypto.resolveTransportBodyLimits，显式上限不足必须报错，不能覆盖；运行时、握手、代理、adapter-node 使用同一派生预算。
- Feedback consoleContent 默认 metadata，仅输出白名单标识与采集状态；summary 需显式选择，操作者自行评估摘要中的业务隐私。
- Reach API 默认 redirect:error，敏感消息始终拒绝重定向；生产敏感消息默认要求 HTTPS。requireHttps:false 是可信内网的显式例外；requireHttps:true 不能与 follow 组合。空成功回执可接受，非空必须是有界 JSON 对象。
- 旧部署凭据仅通过 importDeploymentSecrets / hai deploy-secrets 明确导入，默认预检。固定项目/服务/卷及实际密码认证通过后，共用部署锁原子提交 0600 v2 状态；不覆盖损坏状态、不改 current、不替自定义外部中间件迁移身份。参见[凭据导入](../../../packages/deploy/docs/credential-import.md)。

## 配置消费边界

- 删除没有运行时消费的 Core `debug`、`id` 以及示例 `_core.yml` 中的 `features` / `supportedLocales`。日志使用真实 `logging.level`，ID 前缀与长度使用每次 `core.id` 调用参数，业务开关放应用自己的 Schema；Core Schema 对未知字段明确失败。
- Logger 导入不修改 `LANG` / `LC_ALL` / `PYTHONIOENCODING`。Windows TTY 编码处理不能覆盖用户选择的消息语言或子进程协议。
- MySQL 与 PostgreSQL 的 pool 字段和范围分别定义；URL 优先级、获取连接期限及不支持的字段以实际驱动消费为准。不能用同名通用 pool 对象推断两个驱动都支持 `min` 或 `idleTimeout`。
- Redis Cluster 的主节点密码与配置拓扑分别处理；缓存 SET 的应用/未应用结果、互斥期限和单位不再用成功的 void 混淆。cache 期限以所用选项的秒/毫秒为准，不能跨选项套单位。
- 存储签名只支持 S3；公开 HTTP 入参不包含尚未消费的 `contentLength`。Node 流/checksum 选项不是上传签名能力；具体映射见[存储矩阵](../../../packages/storage/README.md#存储输入约束与跨端能力)。
- RelDB 操作日志不记录 SQL 原文、参数值、DDL 默认值或驱动原始错误。`maxLength` 限制安全数量摘要，0 表示省略摘要，不能描述为“截断后记录原 SQL/参数”。
- kit 限流内存限制同时识别 NODE_ENV 与 HAI_CORE_ENV 的 production。kit/serv 认证 Cookie 默认 Secure 同样识别两者，但不受 HAI_E2E/HAI_E2E_MOCK 放宽；serv 的显式 secure 参数仍优先。
- 生产共享后端、未知外部效果、租约/CAS 的最终提交与重试边界见[共享状态能力表](../../instructions/distributed-state.md)。获得数据库连接、写入缓存或拿到锁都不能替代这些保证。

三语 README 对应相同公开 API；本表集中记录源码消费链，不复制每个模块的完整用法。公开配置修改时必须同时更新实现、应用/CLI 模板、生成目录与环境示例、README、开发 skill、应用 skill 和 LLMS；静态生成检查与真实行为验证分别报告。
