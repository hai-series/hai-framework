# 测试开发规范

> 适用于 tests/ 下的文件的修改。Vitest 测试的编写规范。

## 核心原则

多项门禁按 [工作规范的分轮验证流程](workspace.md#验证与交付) 先收集结果、集中分析修复，再定向确认失败和直接受影响项已解决，通过后才扩大验收；定向回归未通过时继续小范围修复，不从头重跑整套门禁。目标用例的 TDD 小循环保留。

测试临时工程、镜像、容器、辅助进程与数据须在 finally/teardown 自动清理，成功、失败和取消均执行；只清理本次创建的资源。日志、截图与报告保留到分析和交付结束再清理，不提交验收产物。

容器部署夹具先检查固定公开基础镜像，仅确认缺失才拉取。成功 create 后先登记完整 ID，再在该容器的私有 PID namespace 内执行联网准备；异步 exec 转交同一取消信号并等待本地客户端 close，随后按已登记 ID 回收、确认消失。总准备期限早于测试 hook，给停止与核验留出预算；不能只增大超时。公共缓存不清理，私有 tag 清理前复核内容 ID/owner。create 未获得可信回执或测试进程被强杀时保留未知边界，不按名称或 label 认领资源。

浏览器验收的数据库与上传数据放入本轮独立临时目录；Windows 必须等测试子进程和服务退出后再删除，不能依赖下一轮运行清理被锁定的文件。

本仓库并行工作区的根 E2E 可设置 `ADMIN_E2E_BASE_URL`（管理台本机测试地址）和 `MOBILE_E2E_PORT`（移动示例预览端口），避免占用其它项目的开发端口。先确认空闲，不结束未知或其它工作区进程；保留独立服务和数据隔离，不启用复用既有服务。

Playwright 服务子进程须显式装配本轮模块配置，隔离继承的 `HAI_*` / `PUBLIC_*` / `VITE_*` 与开发者 `.env.local`；不得只覆盖数据库路径而继承生产 Provider 或整个 `HAI_DB`。使用托管 `test:e2e` 入口分配的绝对 `HAI_E2E_DATA_ROOT`，仅测试进程显式启用 `HAI_E2E=1`；普通开发与生产仍遵守 dotenv 加载及共享后端守卫。启用 transport 的场景使用本轮可信 SM2 ring 和 registry，不以关闭加密代替客户端验收。

1. **统一入口**：测试通过 `<模块名>.xx` 进入（如 `crypto.asymmetric`、`storage.file`），不直接调用内部实现或工厂函数
2. **从实际场景出发**：验证实际使用时的行为和结果，不做形式覆盖
3. **问题修正**：测试不通过时先审查业务逻辑是否有问题，不直接修改测试迎合实现

## 覆盖范围

测试增删及交付遵循[沟通与同步维护](../../packages/cli/templates/skills/hai-app-create/collaboration.md#测试增删与排错)：合并前确认没有丢失独有场景；说明单元、集成、E2E 各自验证什么，并检查是否需要同步使用文档、配置示例、截图、CLI 模板和调用方。

- **正常路径**：核心功能可用
- **边界路径**：非法输入、空值、格式校验失败、超时
- **参数选项**：可选配置的差异化行为
- **多实现**：如有多种实现（内存/Redis 等），抽象公共测试套件后分别执行
- **跨端能力**：涉及 Node/Browser 时，测试需拆分环境或显式隔离，避免互相污染
- 每个新功能/修复必须有对应测试，变更边界行为时补齐边界用例

## 断言风格

- 始终校验 `result.success`
- 成功时：`expect(result.success).toBe(true)` + 检查返回数据
- 失败时：`expect(result.success).toBe(false)` + 校验 `error.code`
- 不使用 `try/catch` 来断言 HaiResult 型 API
- 流式/AsyncIterable API 使用 `for await...of` 收集关键片段，断言顺序、终止和错误事件

## 组织结构

- 按功能拆分文件：`<模块名>-init.test.ts`、`<模块名>-sm2.test.ts`
- 测试名称清晰表达场景（中文或英文均可，保持模块内一致）
- 避免不稳定断言（随机性、时序依赖）

## 外部依赖

- 避免真实外部依赖：使用注入 + mock（网络/数据库/云服务不直连）
- 如有外部依赖（数据库、缓存等），优先使用 Testcontainers 隔离环境
- 禁止在测试中使用 `console.log` 调试（使用 logger 或 vitest 的 `--reporter`）
